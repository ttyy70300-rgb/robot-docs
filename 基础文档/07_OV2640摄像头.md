# 设备说明：OV2640 摄像头

> 项目：ESP32-S3 两轮差速 ROS2 智能小车
> 文档版本：**v1.0**　｜　正式发布版
> 生成日期：2026-11-07
> 资料目录：`7-CameraOV2640资料/`

## 1. 设备概述

| 项目 | 内容 |
|---|---|
| 型号 | **OV2640**（OmniVision） |
| 类型 | CMOS 彩色图像传感器 + 图像处理器（ISP） |
| 最高分辨率 | **UXGA 1632 × 1232（200 万像素）** |
| 输出格式 | YUV422 / RGB565 / **JPEG（硬件压缩）** |
| 数据接口 | **DVP 并口 8/10 位** + SCCB（类 I2C）控制 |
| 帧率 | 15 fps @UXGA，30 fps @SVGA |
| 供电 | 3.3V（模组内含 1.8V/2.8V 稳压） |
| 镜头 | 视模组而定（常见 2.8mm / 120° 广角） |

> **关键特性：硬件 JPEG 压缩**。这是 ESP32 能把图像送出去的前提——原始 RGB565 一帧 1632×1232×2 = 4MB，JPEG 压缩后仅 30~80KB。

## 3. 接口定义（DVP 并口）

### 3.1 信号清单（共 16 根）

| 信号 | 方向 | 说明 |
|---|---|---|
| **D0 ~ D7** | 输入 | 8 位像素数据 |
| **PCLK** | 输入 | 像素时钟（由摄像头输出） |
| **XCLK** | 输出 | 主时钟（ESP32 提供，24MHz） |
| **VSYNC** | 输入 | 场同步（帧起始） |
| **HREF** | 输入 | 行有效 |
| **SIOD** | 双向 | SCCB 数据（=I2C SDA） |
| **SIOC** | 输出 | SCCB 时钟（=I2C SCL） |
| **PWDN** | 输出 | 掉电（高有效，可接 GND 常开） |
| **RESET** | 输出 | 复位（低有效，可接 3.3V 常开） |

> **最少 12 根**（8 数据 + PCLK + VSYNC + HREF + XCLK），加 SCCB 2 根 = 14 根。
> PWDN/RESET 可硬件固定，省 2 根。

### 3.2 ESP32-S3 参考接线（ESP32-CAM 兼容模组）

| 摄像头 | ESP32-S3 | 备注 |
|---|---|---|
| D0 | GPIO4 | — |
| D1 | GPIO5 | — |
| D2 | GPIO6 | — |
| D3 | GPIO7 | — |
| D4 | GPIO8 | — |
| D5 | GPIO9 | — |
| D6 | GPIO10 | — |
| D7 | GPIO11 | — |
| PCLK | GPIO12 | — |
| XCLK | GPIO13 | ESP32 输出 24MHz |
| VSYNC | GPIO14 | — |
| HREF | GPIO15 | — |
| SIOD | GPIO16 | SCCB |
| SIOC | GPIO17 | SCCB |
| PWDN | -1（接 GND） | 省 IO |
| RESET | -1（接 3.3V） | 省 IO |

> ⚠️ **上表是通用 ESP32-CAM 参考，不是本板实际接线**。用户已完成接线，**实际引脚以用户提供的连线图为准**，接线完成后需在 `cam_cfg.h` 中固化。
> ⚠️ 摄像头需 16 个 IO，与主控电机/屏幕/音频**必然冲突** → 独立板方案（见汇总文档）。

## 4. 方案设计：摄像头走哪块板

由于 DVP 需要 14~16 个 GPIO，而主控板可用 IO 仅 25 个且已被电机/编码器/屏幕/音频占满，**摄像头必须独立**。

### 4.1 方案对比

| 方案 | 硬件 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 独立 ESP32-S3 专做摄像头 | 第 2 块板 | 分工清晰、互不干扰 | 需板间同步 | **✅ 推荐** |
| B. 主控直连 DVP | 1 块板 | 无需额外板 | IO 不够，必须砍屏幕或音频 | ❌ |
| C. 换 USB 摄像头接上位机 | 无需 ESP32 | 最简、画质好 | 废掉 OV2640 | 备选 |

### 4.2 方案 A 架构

```
┌──────────────┐  WiFi/UDP  ┌──────────────┐
│ 视觉板        │ ─────────► │ 笔记本上位机  │
│ ESP32-S3 #2  │  JPEG 流    │ YOLOv8 识别   │
│ + OV2640     │            │ → /detections │
└──────────────┘            └──────────────┘
        ▲
        │ WiFi 控制（分辨率/帧率/启停）
        │
┌──────────────┐
│ 主控板 #1     │
└──────────────┘
```

**关键**：视觉板**不与主控板物理连线**，各自独立连 WiFi，由上位机统一协调。这符合"纯 WiFi"约束。

### 4.3 带宽与延迟

| 参数 | 计算 | 结果 |
|---|---|---|
| SVGA JPEG 单帧 | — | ~40 KB |
| 帧率 | 10 fps | — |
| 码率 | 40KB × 10 | **400 KB/s = 3.2 Mbps** |
| WiFi 2.4G 实测吞吐 | — | 20~50 Mbps |
| **占用率** | 3.2 / 30 | **约 11%** |
| 单帧延迟 | 采集+编码+传输 | **60~120 ms** |

> 与雷达（106 kbps）共用 WiFi 完全无压力。

## 5. 软件抽象设计（`cam` 模块）

### 5.1 模块职责与边界

**负责**：DVP 初始化、传感器配置、JPEG 帧采集、WiFi 推流、分辨率/质量动态调整。
**不负责**：图像识别（上位机做）、云台控制（`srv` 模块做）。

### 5.2 常量与配置宏


### 5.8 采集 + 推流实现

```c
static void task_cam_capture(void *arg)
{
    while (1) {
        camera_fb_t *fb = esp_camera_fb_get();
        if (!fb) {
            g_cam.frames_drop++;
            vTaskDelay(pdMS_TO_TICKS(10));
            continue;
        }
        g_cam.frames_ok++;
        g_cam.last_frame_ms = esp_timer_get_time() / 1000;

        /* 队列满则丢最旧的 */
        if (xQueueSend(s_frame_q, &fb, 0) != pdTRUE) {
            camera_fb_t *old = NULL;
            xQueueReceive(s_frame_q, &old, 0);
            if (old) esp_camera_fb_return(old);
            xQueueSend(s_frame_q, &fb, 0);
            g_cam.frames_drop++;
        }

        /* 控制帧率 */
        uint32_t dt = 1000 / g_cam.fps_target;
        vTaskDelay(pdMS_TO_TICKS(dt));
    }
}

static void task_cam_stream(void *arg)
{
    camera_fb_t *fb = NULL;
    while (1) {
        if (xQueueReceive(s_frame_q, &fb, portMAX_DELAY) != pdTRUE) continue;
        if (!s_stream_enable) { esp_camera_fb_return(fb); continue; }

        /* 分片：每片 [seq(2)][total(2)][idx(2)][len(2)][data] */
        uint16_t total = (fb->len + CAM_CHUNK_SIZE - 1) / CAM_CHUNK_SIZE;
        uint8_t *p = fb->buf;
        for (uint16_t i = 0; i < total; i++) {
            uint16_t len = (fb->len - i * CAM_CHUNK_SIZE > CAM_CHUNK_SIZE)
                         ? CAM_CHUNK_SIZE : (fb->len - i * CAM_CHUNK_SIZE);
            uint8_t *q = s_tx_buf;
            *q++ = 0xAA; *q++ = 0x55;
            uint8_t *len_pos = q++;
            *q++ = CAM_FRAME_ID;
            *q++ = fb->seq >> 8;   *q++ = fb->seq & 0xFF;
            *q++ = total >> 8;     *q++ = total & 0xFF;
            *q++ = i >> 8;         *q++ = i & 0xFF;
            *q++ = len >> 8;       *q++ = len & 0xFF;
            memcpy(q, p, len); q += len;
            uint8_t flen = (uint8_t)(q - s_tx_buf) + 1;
            s_tx_buf[len_pos - s_tx_buf] = flen;
            uint8_t cs = 0;
            for (uint8_t *r = s_tx_buf; r < q; r++) cs += *r;
            *q++ = cs;
            sendto(s_udp_sock, s_tx_buf, q - s_tx_buf, 0,
                   (struct sockaddr *)&g_host_addr, sizeof(g_host_addr));
            p += len;
        }
        esp_camera_fb_return(fb);
    }
}
```

| 任务 | 核心 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|---|
| `task_cam_capture` | 1 | 8 | 4096 | 帧率驱动 | `esp_camera_fb_get()` |
| `task_cam_stream` | 0 | 6 | 4096 | 队列 | 分片 UDP 发送 |

## 6. 上位机侧：视觉识别管线

### 6.1 数据流

```
UDP 8891 ──► cam_bridge(重组 JPEG) ──► /image_raw (sensor_msgs/Image)
                                          │
                                          ▼
                                    cv_bridge + YOLOv8
                                          │
                                          ▼
                                   /detections (自定义 msg)
                                          │
                                          ▼
                              导航/跟随决策节点
```

### 6.2 识别建议

| 任务 | 模型 | 输入尺寸 | 帧率（笔记本 CPU） | 帧率（GPU） |
|---|---|---|---|---|
| 目标检测 | YOLOv8n | 640 | 8~12 fps | 60+ fps |
| 人脸检测 | Haar / MediaPipe | 320 | 25 fps | — |
| 巡线 | 传统 CV（阈值+最小二乘） | 320×240 | 30 fps | — |
| AR 标签 | ArUco | 640 | 20 fps | — |

> **不要指望 ESP32 做识别**。ESP32-S3 无 NPU，跑 MobileNet 推理 1~2 fps，没有实用价值。

### 6.3 视觉→控制的闭环延迟

| 环节 | 延迟 |
|---|---|
| 曝光 + 采集 | 33~66 ms |
| JPEG 编码（硬件） | 10~20 ms |
| WiFi 传输 | 30~60 ms |
| 解码 + 推理 | 30~80 ms |
| **端到端** | **100~220 ms** |

> 结论：**视觉只能做"慢速决策"**（识别到人→停下、识别到球→转向），**不能做高速视觉伺服**。

## 7. 错误处理与自检

| 检查 | 方法 | 处理 |
|---|---|---|
| 传感器 ID | 读 SCCB 0x0A/0x0B，应为 `0x26 0x42` | 失败 → 上报离线 |
| 帧超时 | 500ms 无新帧 | 重新初始化传感器 |
| 帧率过低 | 实际 fps < 目标 50% | 降分辨率或提高 quality 值 |
| 丢帧率高 | `drop/ok > 20%` | 检查 WiFi 带宽、降低帧率 |
| 花屏/绿屏 | JPEG 分片乱序 | 检查 seq/total/idx 字段 |
| 过热 | 长时间 UXGA | 降分辨率，加散热 |

## 8. 与上位机的契约

## 10. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 初始化失败 | XCLK 未输出 / PWDN 悬空 | 检查 24MHz、PWDN 接 GND |
| 图像全绿 | 数据线序错 / 时钟太快 | 降 XCLK 到 20MHz，核对 D0~D7 |
| 图像撕裂 | PSRAM 带宽不足 | 降分辨率，`fb_count=1` |
| 花屏 | 排线过长 / 干扰 | 缩短排线 <10cm，加地线 |
| 帧率上不去 | JPEG 质量太高 / WiFi 拥塞 | 调 quality=15，降分辨率 |
| 摄像头发热 | 长时间高分辨率 | 降帧率，间歇采集 |
