> 项目：ESP32-S3 两轮差速 ROS2 智能小车

## 1. 设备概述

| 项目 | 内容 |
|---|---|
| 模块名称 | LMD2718 + NS4168 音频模块（鹿小班科技） |
| 麦克风 | **LMD2718T** MEMS 电容麦克风（**PDM 数字输出**） |
| 功放 | **NS4168** I2S 输入单声道 Class-D（**2.5W**） |
| 喇叭接口 | 1.25mm 2P（外接 4Ω/3W 喇叭） |
| 与主控接口 | I2S（功放）+ PDM（麦克风）+ 5V/GND |
| 模块尺寸 | 16.7 × 18.2 mm，排针间距 2.54mm |
| 板载 | 3.3V 稳压芯片 |

> **注意**：本模块**只有麦克风和功放，没有语音识别芯片**。
> **本项目方案（v2）**：端侧只做 PDM 采集 + 能量 VAD + PCM 推流，**语音识别全部在上位机**（sherpa-onnx 流式）。
> 详见 §5。

## 2. 关键参数

### 2.1 LMD2718T MEMS 麦克风

| 项目 | 数值 |
|---|---|
| 类型 | 电容式 MEMS，集成前置放大 ASIC |
| 工作电压 | 1.8 ~ 3.3 V（典型 2.5V） |
| 工作电流 | ≤500 µA（典型 300 µA） |
| **灵敏度** | **-38 dB ±1 dB**（1kHz，94dB SPL） |
| **信噪比 SNR** | **≥62 dB**（A 计权） |
| 频率响应 | 20 Hz ~ 20 kHz |
| THD | ≤1%（1kHz，94dB SPL） |
| 声压级范围 | 30 ~ 120 dB SPL |
| **输出格式** | **单比特 PDM（脉冲密度调制）** |
| PDM 时钟 | 1.024 ~ 3.072 MHz（对应 8~96kHz 采样率） |
| 封装 | 3.5 × 2.65 × 0.95 mm |

> **PDM 要点**：只有 CLK 和 DATA 两根线。ESP32-S3 的 I2S 外设支持 **PDM RX 模式**，硬件自动抽取滤波，无需软件解调。

### 2.2 NS4168 功放

| 项目 | 数值 |
|---|---|
| 类型 | 单声道 Class-D，**I2S 数字输入**（内置 DAC） |
| 输出功率 | **2.5 W**（VDD=5V，RL=4Ω） |
| 工作电压 | **3.0 ~ 5.5 V** |
| 效率 | 80%（5V/4Ω/2.5W） |
| THD+N | 0.2%（5V/4Ω/Po=1W） |
| 采样率 | **8 kHz ~ 96 kHz** |
| 声道 | 左右可选（CTRL 脚电平） |
| 保护 | 过流 / 过热 / 欠压 |
| 封装 | ESOP8 |
| 特点 | 无需输出滤波器、上电/掉电噪声抑制、防失真 NCN |

## 4. 音频链路架构

```
                     ┌─────────────────────────────────┐
   说话 ──► LMD2718 ──┤ PDM CLK/DATA                    │
                     │                                 │
                     │        ESP32-S3                 │
                     │                                 │
   喇叭 ◄── NS4168 ◄──┤ I2S0 TX (BCLK/LRCLK/SDATA)      │
                     │                                 │
                     │  PDM → PCM → RMS VAD → UDP 推流  │
                     └─────────────────────────────────┘
```

### 4.1 两条通道共用 I2S0（⚠️ 这是硬约束）

| 通道 | 外设 | 方向 | 用途 |
|---|---|---|---|
| **录音** | **I2S0 RX（PDM 模式）** | 输入 | VAD 触发的语音流推给上位机 |
| **放音** | **I2S0 TX（标准 I2S）** | 输出 | 上位机 TTS 播报、本地提示音 |

### 4.2 ⚠️ 单 I2S 全双工的采样率约束

ESP32-S3 有 2 个 I2S 控制器，本项目**只用 I2S0 同时做 RX 与 TX**（另一个留给扩展）。

**这带来一条不能破的约束：**

> **PDM RX 与标准 I2S TX 共用同一控制器时，采样率必须完全一致。**

原因在硬件层：同一个 I2S 控制器只有一个时钟分频器（`clkm_div_num` / `clkm_div_b` / `a/b` 小数分频），TX 和 TX/RX 共享同一路 `MCLK`。想跑两个不同采样率，只能：

| 方案 | 可行性 | 结论 |
|---|---|---|
| 同时收发不同采样率（如 RX 16k + TX 44.1k） | ❌ 需要不同 MCLK | **不可行** |
| 收发都用 16 kHz | ✅ 共用一套时钟 | **本项目采用** |
| 播放时暂停录音 / 录音时暂停播放 | ✅ 分时复用，可换采样率 | 降级方案（会丢语音） |
| 用 I2S0 + I2S1 各管一个方向 | ✅ 独立时钟 | 但要多占 2~3 个引脚，板 3 有富余时可考虑 |

**因此本项目全链路锁死 16 kHz：**

| 用途 | 采样率 | 位深 | 声道 |
|---|---|---|---|
| 语音采集（PDM → PCM，VAD + 推流） | **16 kHz** | 16 bit | 单声道 |
| ASR 输入（上位机 sherpa-onnx） | **16 kHz** | 16 bit | 单声道 |
| TTS 输出（edge-tts / piper 生成后重采样） | **16 kHz** | 16 bit | 单声道 |
| 本地提示音（SPIFFS 里的 WAV） | **16 kHz** | 16 bit | 单声道 |

> **PDM 时钟** = 采样率 × 64 = **1.024 MHz**。
> **I2S TX** 的 `BCLK` = 16k × 32（每帧 2 声道 × 16 bit）= **512 kHz**。
>
> 这两个时钟都由同一个 I2S0 的 MCLK 分频而来，比例固定，所以**不能只改其中一个**。

**实现要点**

```c
/* 一次配好 I2S0 的时钟，TX 与 RX 共用 */
i2s_chan_config_t chan_cfg = I2S_CHANNEL_DEFAULT_CONFIG(I2S_NUM_0, I2S_ROLE_MASTER);
chan_cfg.auto_clear = true;
i2s_new_channel(&chan_cfg, &s_tx_h, &s_rx_h);   /* 同时拿到 TX 与 RX 句柄 */

/* TX：标准 I2S，16k */
i2s_std_config_t tx_cfg = {
    .clk_cfg  = I2S_STD_CLK_DEFAULT_CONFIG(16000),
    .slot_cfg = I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_16BIT,
                                                    I2S_SLOT_MODE_STEREO),
    .gpio_cfg = { .mclk = I2S_GPIO_UNUSED, .bclk = AUD_PIN_BCLK,
                  .ws = AUD_PIN_LRCLK, .dout = AUD_PIN_SDATA, .din = I2S_GPIO_UNUSED },
};
i2s_channel_init_std_mode(s_tx_h, &tx_cfg);

/* RX：PDM，同样 16k（→ PDM 时钟 1.024MHz） */
i2s_pdm_rx_config_t rx_cfg = {
    .clk_cfg  = I2S_PDM_RX_CLK_DEFAULT_CONFIG(16000),
    .slot_cfg = I2S_PDM_RX_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_16BIT,
                                               I2S_SLOT_MODE_MONO),
    .gpio_cfg = { .clk = AUD_PIN_PDM_CLK, .din = AUD_PIN_PDM_DATA,
                  .invert_flags = { .clk_inv = false } },
};
i2s_channel_init_pdm_rx_mode(s_rx_h, &rx_cfg);
```

> ⚠️ **踩坑提示**：如果先把 RX 配成 16k、再把 TX 配成 44.1k，`i2s_channel_init_std_mode()` 会返回 `ESP_ERR_INVALID_STATE` 或直接改掉 RX 的时钟导致录音变调。**一旦确定 16k，两处都不能单独改。**

> 若后期确实需要放 44.1k 音乐，正确做法是**在上位机把音频重采样到 16k 再推流**，而不是在设备端改采样率。

## 5. 语音方案设计（v2 · 识别在上位机）

> ⚠️ **本节在 2026-11-07 修订**：语音识别从 ESP32 端侧改到上位机（笔记本）。
> 板 3 只负责"采音 / 放音 / 判断有没有人说话"，**不做任何识别**。

### 5.1 职责重新划分

| 环节 | 运行位置 | 技术 | 说明 |
|---|---|---|---|
| 采音 | **板 3** | PDM 16kHz | LMD2718 |
| **VAD（有人说话吗）** | **板 3** | 能量门限（RMS） | 极轻，几行代码 |
| 推流 | **板 3** | UDP `0x23` | 只在说话时推，省带宽 |
| **ASR（说了什么）** | **上位机** | **sherpa-onnx 流式** | 主链路，300~800ms |
| 意图解析 | 上位机 | 规则 / LLM | 文本 → 动作 |
| TTS | 上位机 | piper / edge-tts | 文本 → PCM |
| 放音 | **板 3** | I2S → NS4168 | 收 `0x53` |

### 5.2 数据流

```
说话 ──PDM──► 板3 ──RMS VAD──► 检测到语音 ──0x23 PCM 分片──► 上位机
                                                              │
                                              sherpa-onnx 流式识别
                                                              │
                                                        文本 → 意图
                                                              │
                                        ┌─────────────────────┼─────────────┐
                                        ▼                     ▼             ▼
                                  /cmd_vel 或 Nav2      0x52 屏幕提示   0x53 TTS PCM
                                                              │             │
                                                              ▼             ▼
                                                          板1 屏幕      板3 喇叭
```

### 5.3 为什么改到上位机（三条理由）

| 理由 | 说明 |
|---|---|
| 识别质量 | 端侧 MultiNet 只有 20~200 条固定词；上位机可跑任意语句，还能接 LLM 做语义理解 |
| 释放 Flash/RAM | esp-sr 模型占 ~2MB 分区 + ~130KB RAM，板 3 现在极轻 |
| 迭代速度 | 改命令词只改上位机配置，不用重新烧固件、不用重新训练模型 |

**代价（必须接受）**：延迟从 <500ms 变成 **0.5~1s**（流式）或 1.5~3s（批量 Whisper）。

### 5.4 延迟预算与能力边界

| 环节 | 耗时 |
|---|---|
| VAD 判定（10ms 帧 × 5 帧确认） | 50 ms |
| PCM 分片上行（WiFi） | 20 ms |
| sherpa-onnx 流式识别 | 300~800 ms |
| 意图解析 | 50 ms |
| **合计（到执行）** | **0.4~0.9 s** |

> 🔴 **由此划定的能力边界**：
> - ✅ **任务级指令**：开始建图 / 保存地图 / 导航到厨房 / 回到起点 / 拍照
> - ❌ **实时运动指令**：前进一点 / 左转 / 停 —— 说"停"之后车还会走 0.5~0.9 秒
>
> **实时运动走键盘/手柄/Web 摇杆**；**急停必须是屏幕按钮 + 物理按钮，绝不挂语音链路**。

### 5.5 上位机 ASR 选型

| 方案 | 延迟 | 中文 | 离线 | 建议 |
|---|---|---|---|---|
| **sherpa-onnx**（流式） | 300~800ms | 好 | ✅ | **✅ 主链路** |
| Vosk | 300~500ms | 一般 | ✅ | 备选 |
| faster-whisper | 1~3s | 很好 | ✅ | 长句兜底 |
| 讯飞/百度云 | ~500ms | 最好 | ❌ | 要联网 + 费用 |

### 5.6 TTS 方案

| 方案 | 实现 | 音质 | 推荐 |
|---|---|---|---|
| **上位机 TTS → PCM 推流** | piper / edge-tts → `0x53` | 很好 | **✅ 首选**（统一走这条） |
| 板端预录 WAV | 存 Flash，固定提示音 | 好 | ✅ 补充（开机音、"嘀"） |

> 板端只保留**极少量固定提示音**（开机、错误 "嘀"），所有语音播报走上位机 TTS。

## 6. 软件抽象设计（`aud` 模块）

### 6.1 模块职责与边界

**负责**：I2S 初始化（TX/RX）、PDM 采集、**能量 VAD**、PCM 分片推流、播放、音量控制、音频事件上报。
**不负责**：语音识别（上位机 sherpa-onnx）、语义理解（上位机）、动作映射（`sys` 模块）。

### 6.2 常量与配置宏

```c
/* aud_cfg.h */
#define AUD_I2S_PORT            I2S_NUM_0

/* 放音（NS4168） */
#define AUD_PIN_BCLK            15
#define AUD_PIN_LRCLK           16
#define AUD_PIN_SDATA           7
#define AUD_TX_SAMPLE_RATE      16000
#define AUD_TX_BITS             16

/* 录音（LMD2718 PDM） */
#define AUD_PIN_PDM_CLK         2
#define AUD_PIN_PDM_DATA        3
#define AUD_RX_SAMPLE_RATE      16000
#define AUD_RX_BITS             16
#define AUD_PDM_DOWNSAMPLE      64          /* PDM 时钟 = 16k × 64 = 1.024MHz */

/* 缓冲 */
#define AUD_TX_BUF_MS           100
#define AUD_RX_BUF_MS           100
#define AUD_VOICE_QUEUE_LEN     4

/* 音量 */
#define AUD_VOL_DEFAULT         70          /* 0~100 */
#define AUD_VOL_MAX             100

/* VAD（能量门限，端侧唯一"智能"） */
#define AUD_VAD_FRAME_MS        10          /* 每帧 10ms = 160 样本 */
#define AUD_VAD_FRAME_SAMPLES   (AUD_RX_SAMPLE_RATE / 100)
#define AUD_VAD_THRESHOLD_DBFS  (-42.0f)    /* 说话门限，需现场标定 */
#define AUD_VAD_HANGOVER_MS     600         /* 静音多久判定说完 */
#define AUD_VAD_MIN_SPEECH_MS   200         /* 太短不算一句话 */

/* 录音上传 */
#define AUD_UPLOAD_FRAME_ID     0x23
#define AUD_UPLOAD_PORT         8892
#define AUD_UPLOAD_MAX_MS       8000        /* 单次最长录音 */
#define AUD_UPLOAD_CHUNK        1024        /* 每片字节数 */
```

> 端侧**没有任何模型文件**，`aud` 模块只做采样、算 RMS、打包、发送。

### 6.3 数据结构

```c
/* 音频事件（上报给上位机，也用于本地显示） */
typedef enum {
    AUD_EVT_NONE = 0,
    AUD_EVT_VAD_START = 1,      /* 检测到说话，开始推流 */
    AUD_EVT_VAD_END   = 2,      /* 说话结束，停止推流 */
    AUD_EVT_PLAY_DONE = 3,      /* 上位机下发的 PCM 播完 */
    AUD_EVT_OVERFLOW  = 4,      /* 缓冲溢出（丢帧） */
} aud_evt_type_t;

typedef struct {
    aud_evt_type_t type;
    uint32_t       stamp_ms;
    uint32_t       param;       /* VAD_END 时=本段语音时长 ms */
} aud_evt_t;

/* 音频状态 */
typedef struct {
    bool     inited;
    bool     mic_ok;
    bool     spk_ok;
    bool     streaming;         /* 正在推流 */
    bool     speaking;          /* 正在播放 */
    uint8_t  volume;
    float    last_rms_dbfs;     /* 最近一帧能量，调试用 */
    uint32_t evt_cnt;
    uint32_t play_bytes;
    uint32_t rec_bytes;
} aud_status_t;

/* 播放请求 */
typedef struct {
    const uint8_t *data;    /* PCM 数据指针（必须持久有效） */
    uint32_t       len;     /* 字节数 */
    bool           blocking;
} aud_play_req_t;
```

### 6.8 关键实现

```c
/* I2S TX 初始化（NS4168） */
static esp_err_t aud_tx_init(void)
{
    i2s_chan_config_t chan_cfg = I2S_CHANNEL_DEFAULT_CONFIG(AUD_I2S_PORT, I2S_ROLE_MASTER);
    chan_cfg.auto_clear = true;
    ESP_RETURN_ON_ERROR(i2s_new_channel(&chan_cfg, &s_tx_h, NULL), TAG, "new tx");

    i2s_std_config_t std_cfg = {
        .clk_cfg  = I2S_STD_CLK_DEFAULT_CONFIG(AUD_TX_SAMPLE_RATE),
        .slot_cfg = I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_16BIT,
                                                        I2S_SLOT_MODE_MONO),
        .gpio_cfg = {
            .mclk = I2S_GPIO_UNUSED,
            .bclk = AUD_PIN_BCLK,
            .ws   = AUD_PIN_LRCLK,
            .dout = AUD_PIN_SDATA,
            .din  = I2S_GPIO_UNUSED,
        },
    };
    ESP_RETURN_ON_ERROR(i2s_channel_init_std_mode(s_tx_h, &std_cfg), TAG, "std tx");
    return i2s_channel_enable(s_tx_h);
}

/* I2S RX 初始化（PDM 麦克风） */
static esp_err_t aud_rx_init(void)
{
    i2s_chan_config_t chan_cfg = I2S_CHANNEL_DEFAULT_CONFIG(AUD_I2S_PORT, I2S_ROLE_MASTER);
    chan_cfg.auto_clear = true;
    ESP_RETURN_ON_ERROR(i2s_new_channel(&chan_cfg, NULL, &s_rx_h), TAG, "new rx");

    i2s_pdm_rx_config_t pdm_cfg = {
        .clk_cfg  = I2S_PDM_RX_CLK_DEFAULT_CONFIG(AUD_RX_SAMPLE_RATE),
        .slot_cfg = I2S_PDM_RX_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_16BIT,
                                                   I2S_SLOT_MODE_MONO),
        .gpio_cfg = {
            .clk  = AUD_PIN_PDM_CLK,
            .din  = AUD_PIN_PDM_DATA,
            .invert_flags = { .clk_inv = false },
        },
    };
    ESP_RETURN_ON_ERROR(i2s_channel_init_pdm_rx_mode(s_rx_h, &pdm_cfg), TAG, "pdm rx");
    return i2s_channel_enable(s_rx_h);
}
```

### 6.9 任务

| 任务 | 核心 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|---|
| `task_mic` | 1 | 9 | 4096 | 连续 DMA 读 | PDM → PCM，写入环形缓冲 |
| `task_vad` | 1 | 8 | 3072 | 10ms | 算 RMS → 判定起止 → 触发推流 |
| `task_tx` | 0 | 7 | 4096 | 队列 | 分片打包 → UDP 发送 |
| `task_play` | 0 | 5 | 4096 | 队列 | 收 `0x53` → I2S 播放 |

> 端侧没有推理，CPU 占用 <5%。**但仍要绑核**：`task_mic`/`task_vad` 放 Core1 与采样同侧，`task_tx`/`task_play` 放 Core0 走网络。

### 6.10 VAD 实现要点

```c
/* 每 10ms 一帧（160 样本 @16kHz），算 dBFS */
static float frame_dbfs(const int16_t *pcm, int n)
{
    float sum = 0;
    for (int i = 0; i < n; i++) sum += (float)pcm[i] * pcm[i];
    float rms = sqrtf(sum / n);
    return 20.0f * log10f(rms / 32768.0f + 1e-9f);
}

/* 自适应噪声底 + 滞回判定 */
void vad_step(const int16_t *pcm, int n)
{
    float db = frame_dbfs(pcm, n);
    g_aud.last_rms_dbfs = db;

    if (db < s_noise_floor_dbfs + 6.0f)          /* 安静时更新噪声底 */
        s_noise_floor_dbfs = 0.98f * s_noise_floor_dbfs + 0.02f * db;

    float on_th  = s_noise_floor_dbfs + 12.0f;   /* 起始门限 */
    float off_th = s_noise_floor_dbfs + 6.0f;    /* 结束门限（滞回） */

    if (!g_aud.streaming && db > on_th) {
        g_aud.streaming = true;
        s_silence_ms = 0;
        aud_emit_evt(AUD_EVT_VAD_START, 0);
    } else if (g_aud.streaming) {
        s_silence_ms = (db < off_th) ? s_silence_ms + AUD_VAD_FRAME_MS : 0;
        if (s_silence_ms >= AUD_VAD_HANGOVER_MS) {
            g_aud.streaming = false;
            aud_emit_evt(AUD_EVT_VAD_END, s_total_ms);
        }
    }
}
```

> **为什么不用固定阈值**：风扇、空调、电机噪声会让固定阈值失效。自适应噪声底 + 滞回，是最省事又够用的做法。
> 调试时把 `last_rms_dbfs` 显示在屏幕上，现场观察 30 秒就能把门限调对。

## 7. 上位机侧音频链路（替代原 esp-sr 章节）

### 7.1 进程与话题

```
audio_bridge (rclpy)
  ├─ 收 UDP 8892 帧：0x23 PCM 分片 → 重组 → 发布 /audio/in (AudioData)
  ├─ 收 /audio/out (AudioData) → 分片 → 0x53 → 板3 播放
  ├─ 收 0x14 事件 → 发布 /audio/events
  └─ 发 0x14'（可选）→ 让板3 播提示音

voice_asr (sherpa-onnx)
  └─ 订阅 /audio/in → 流式识别 → /voice/text → 意图解析 → /voice/intent

voice_tts (piper / edge-tts)
  └─ 订阅 /voice/say (String) → 合成 PCM → /audio/out
```

### 7.2 sherpa-onnx 配置建议

| 项 | 建议 |
|---|---|
| 模型 | `sherpa-onnx-streaming-zipformer-zh-14M` 或 `paraformer-zh` |
| 采样率 | 16 kHz（与端侧一致，**不做重采样**） |
| 端点检测 | 用 sherpa 自带 VAD，与端侧 VAD 二级确认 |
| 线程 | 2~4 线程，CPU 占用 10~20% |
| 输出 | 增量文本 + 最终文本 |

### 7.3 意图映射（规则优先）

```python
INTENTS = {
    "开始建图": ["开始建图", "建图", "扫描房间"],
    "保存地图": ["保存地图", "存图"],
    "导航":     ["导航到", "去", "带我"],
    "停止":     ["停", "停止", "别动"],      # 注意：语义上的"停"仍有 0.5s 延迟
    "拍照":     ["拍照", "拍一张"],
    "云台回中": ["看这边", "回中"],
}
```

> 规则匹配不中时，可选接入 LLM 做语义理解（本地 Ollama 或 API）。
> **但"停"这个意图不要依赖语音**，见 §5.4。

### 7.4 资源占用

| 项 | CPU | RAM |
|---|---|---|
| audio_bridge | <2% | 20 MB |
| sherpa-onnx（流式中文） | 10~20% | 200~400 MB |
| piper TTS | 5~10%（合成时） | 100 MB |

> 相比端侧 esp-sr（130KB RAM），上位机方案吃 500MB 内存——但笔记本不缺这个。

## 8. 错误处理与自检

| 检查 | 方法 | 处理 |
|---|---|---|
| 麦克风无数据 | PDM 读取 100ms 全 0 | 上报 mic 故障 |
| 麦克风饱和 | 连续帧 dBFS > -3 | 提示"离太近/太吵"，必要时软件衰减 |
| 功放无输出 | 播放后测不到电流变化（需硬件） | 无法软件检测，靠听 |
| 推流丢包 | 上位机连续 3 帧缺片 | 丢弃本段，发 `0x14` 通知重说 |
| 播放卡顿 | 队列积压 | 增大 TX 缓冲，或降 TTS 码率 |
| VAD 误触发 | 环境噪声突变 | 自适应噪声底 + 提高门限 |

## 9. 与上位机的契约

### 9.1 上行：音频事件 `0x14`

| 字段 | 类型 | 说明 |
|---|---|---|
| `evt_type` | uint8 | 1=VAD开始 2=VAD结束 3=播放完成 4=溢出 |
| `param` | uint32 | VAD_END 时为语音时长 ms，其余为 0 |

帧长 5 字节，事件驱动。

### 9.2 上行：录音流 `0x23`

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | uint16 | 片序号（每段语音从 0 开始） |
| `total` | uint16 | 总片数 |
| `idx` | uint16 | 当前片 |
| `len` | uint16 | 本片字节数 |
| `pcm[]` | int16 | 16kHz/16bit/单声道 |

UDP 端口 **8892**，仅在 VAD 判定"在说话"时发送。

### 9.3 下行：播放请求 `0x53`

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | uint8 | 0=停止 1=播放PCM 2=播放文件 3=设置音量 |
| `param` | uint8 | 音量或文件 ID |
| `len` | uint16 | PCM 字节数（type=1 时） |
| `pcm[]` | int16 | PCM 数据（16kHz/16bit/单声道） |

## 11. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 没声音 | 5V 没接（只接 3.3V） | **必须 5V** |
| 声音很小 | 喇叭阻抗不匹配 | 用 4Ω，检查软件增益 |
| 噪声大 | PDM 时钟干扰 / 电源纹波 | 加 LC 滤波，缩短排线 |
| 啸叫 | 麦克风离喇叭太近 | 物理隔离 + 降低音量 |
| VAD 一直触发 | 门限太低 / 环境噪声大 | 提高 `AUD_VAD_THRESHOLD_DBFS` |
| VAD 不触发 | 门限太高 / 麦克风增益小 | 看 `last_rms_dbfs` 现场调 |
| 识别不准 | 端侧音质差 / 采样率不匹配 | 确认 16kHz，加 AEC 或离麦近点 |
| 播放断续 | I2S 缓冲不足 | 增大 `AUD_TX_BUF_MS` |
