## 1. 这台机器的角色

它同时承担两个角色，这两个角色对软件的要求不同：

| 角色 | 做什么 | 关键要求 |
|---|---|---|
| **开发机** | 写固件（ESP32）、写上位机（ROS2/Python）、写前端（Vue） | 编译工具链、IDE、Git |
| **上位机（运行期）** | 跑 ROS2 节点、SLAM、Nav2、YOLO、语音识别、Web 网关 | CPU/GPU 算力、WSL 网络模式、低延迟 |

这决定了它不是"随便一台笔记本"：**WSL 的网络模式、GPU 的可见性、CPU 的核数**都直接影响系统能不能跑起来。

### 5.2 `.wslconfig`（**最关键的一项**）

位置：`C:\Users\Guo\.wslconfig`

```ini
[wsl2]
networkingMode=mirrored    # ★ 核心：WSL 直接用宿主 IP
dnsTunneling=true
autoProxy=true
firewall=true

[experimental]
autoMemoryReclaim=gradual
sparseVhd=true
```

**为什么必须开 `mirrored`：**

默认的 NAT 模式下，WSL 有独立的虚拟 IP（`172.27.x.x`）。ESP32 在局域网里**无法访问这个地址**，而 `netsh portproxy` 只支持 TCP，项目的 UDP 协议（8888/8889/8891/8892）全部收不到。

开启后的实测结果：

| 项 | NAT 模式（改之前） | mirrored 模式（现在） |
|---|---|---|
| WSL IP | 172.27.150.254 | **192.168.3.30**（与 Windows 相同） |
| 网关 | 172.27.144.1 | 192.168.3.1（真实路由器） |
| ESP32 → 上位机 UDP | ❌ 不可达 | ✅ **已验证** |

**验证记录：**

```
Windows 发送 PING-FROM-WINDOWS → 192.168.3.30:8888
WSL 收到: b'PING-FROM-WINDOWS'  来源: 192.168.3.30:55377
入站测试: PASS
```

### 5.3 网络现状

```
接口:
  lo      127.0.0.1/8
  lo      10.255.255.254/32      ← mirrored 模式特征（DNS 隧道）
  eth1    169.254.83.107/16      ← 链路本地（WSL 内部）
  eth2    192.168.3.30/24        ← ★ 真实局域网，与 Windows 同 IP

默认网关: 192.168.3.1
DNS     : 10.255.255.254（隧道）
```

> **代理**：Windows 上的代理端口为 `6696`。在 WSL 内部，`127.0.0.1:6696` 可用（mirrored 模式下回环共享）；NAT 模式下需用网关 IP。

### 6.3 为什么锁死 torch 2.1.2

| 事实 | 推论 |
|---|---|
| GTX 950M = **Maxwell 架构，compute capability 5.0（sm_50）** | 需要 wheel 内含 sm_50 的 SASS |
| PyTorch 从 2.6 起**移除了 sm_50 支持** | 2.5 以上装上也跑不了 |
| 驱动是 R580 分支（CUDA 13.0） | R580 是**最后一个支持 Maxwell 的驱动系列** |

**因此：`torch==2.1.2+cu118` 是这台机器的正确版本，不要升级。**

> 若某天误升级导致 `torch.cuda.is_available()` 变 False，回滚命令：
> ```bash
> pip install --index-url https://download.pytorch.org/whl/cu118 \
>   torch==2.1.2+cu118 torchvision==0.16.2+cu118
> ```

## 7. 关键技术决策与依据

### 7.1 为什么 CPU 核数是硬约束

**i5-6300HQ 是 4 核 4 线程，没有超线程。**这是整台机器最紧的资源，比显卡更紧。

| 任务 | 占用 |
|---|---|
| ROS2 核心 + 桥接节点 | ~0.4 核 |
| `slam_toolbox` | 0.5~0.8 核 |
| Nav2（导航时） | ~0.6 核 |
| `sherpa-onnx` 流式中文 | 1~1.5 核 |
| `web_gateway` | ~0.2 核 |
| YOLOv8n（GPU） | ~0.3 核 + GPU 60~80% |
| **稳态合计** | **~3.1 / 4 核（78%）** |

**由此确定的四条纪律**（已写入 `13` §10.3）：

1. YOLO **间歇跑**——默认 3fps，识别到目标才升 10fps
2. **rviz2 不常开**——单吃 1 核 + GPU；改用 Foxglove（Windows 侧）
3. **4 个桥接节点合并成一个进程**——省 4 个 Python 解释器开销
4. 建图时降低 ASR 线程数，或只在停车时接语音

### 7.2 为什么用 Foxglove 而不是 rviz2

| 项 | rviz2 | Foxglove Studio |
|---|---|---|
| 运行位置 | WSL（吃宿主 CPU） | **Windows 原生** |
| CPU 占用 | ~1 核 + GPU | 不占 WSL 资源 |
| 安装 | ROS2 自带 | 已装 2.9.0 |
| 连接方式 | — | `ws://localhost:8765`（foxglove_bridge） |

对 4 核机器来说，把可视化挪到 Windows 侧是**实打实省下 25% 算力**。

### 7.3 为什么 pip 源用清华、apt 用阿里

实测这台机器的网络是"半通"：

| 目标 | 状态 |
|---|---|
| `pypi.org` / `github.com`（走代理） | ✅ 200 |
| `mirrors.tuna.tsinghua.edu.cn` | ✅ 200 |
| `mirrors.aliyun.com` | ✅ 200 |
| **`packages.ros.org`** | ❌ 不通（需代理） |

所以：apt 走阿里 + 清华 ROS2 镜像（不需要代理）；pip 走清华；只有 PyTorch 官方 wheel 和 GitHub 需要代理。

### 9.2 ⚠️ 两个被版本锁死的包

这是本环境最容易踩的两个雷，升级任何一个都会静默坏掉功能：

| 包 | 锁定版本 | 升级后的后果 |

### 9.3 ⚠️ setup_wsl.sh 的 v1 缺陷（已在 v2 修复）

**v1 为什么"只完成一半"**，根因很隐蔽：

```bash
# v1 的写法（有问题）
MISSING=()                    # 收集所有未安装的包
for p in "${ROS_PKGS[@]}"; do
    dpkg -s "$p" >/dev/null 2>&1 || MISSING+=("$p")
done
sudo apt-get install -y "${MISSING[@]}"   # ← 一条命令装全部
```

`apt-get install` 面对**任意一个不存在的包名**会整条失败（`E: Unable to locate package`，exit 100），**一个包都不装**。而 v1 只 `warn` 了一句"部分包安装失败"，把真实错误吞掉了。

同样的问题在补齐时又复现了一次：我误写了 `ros-humble-rosbag2-storage-mcap-py`（不在 apt 里），导致同批的 `gnupg`、`python3-rosdep`、`python3-colcon-common-extensions` 全部没装上。

**v2 的修复**：

| 改动 | 说明 |
|---|---|
| **逐个安装** | `apt_install_one()` 每个包单独 `apt-get install`，一个失败不影响其他 |
| **失败清单** | 结束后汇总打印所有失败项，不再哑失败 |
| **补全工具** | 加上 `python3-rosdep`、`python3-colcon-common-extensions`、`libsndfile1` |
| **补全包** | 加上 `twist-mux`、`robot-state-publisher`、`rosbag2-storage-mcap`、`diagnostic-updater` |
| **补全 pip** | 加上 `transforms3d`、`soundfile`（锁 0.12.1） |
| **torch 步骤** | 新增 §6，自动检测 GPU 并按锁死版本安装 |
| **rosdep 步骤** | 新增 init/update，并验证能否解析依赖 |
| **colcon 优先 apt** | 用 `/usr/bin/colcon`，不依赖 `~/.local/bin` 是否在 PATH |

### 9.4 ⚠️ WSL 内存偏紧

当前 WSL 只分到 **9.6 GB**（物理内存的 50%）。同时跑 `slam_toolbox` + `Nav2` + `sherpa-onnx` + YOLO 时可能吃紧。

如需调整，在 `.wslconfig` 的 `[wsl2]` 段增加一行后 `wsl --shutdown`：

```ini
memory=12GB
```

### 9.5 ⚠️ mirrored 模式的端口共存

Windows 与 WSL 共享同一个 IP 和端口空间。如果 Windows 上有程序占用 8080，会与 WSL 里的 `web_gateway` 冲突。

用这条命令排查端口占用：

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen -EA SilentlyContinue
```

### 9.6 ⚠️ 代理与 pio 的冲突

**PlatformIO 走代理反而会卡死**（实测：开代理时下载停在几 MB 不动，关掉代理直连立刻正常）。

以后用 `pio` 装平台/库时，**先确认代理环境变量已清空**：

```powershell
Remove-Item Env:HTTP_PROXY -EA SilentlyContinue
Remove-Item Env:HTTPS_PROXY -EA SilentlyContinue
```

而 **PyTorch 下载相反，必须走代理**（直连 0.57 MB/s，代理 5 MB/s）。

### 9.7 ⚠️ PlatformIO 的 riscv 工具链已改为可选

`espressif32` 8.0.0 把 `toolchain-riscv32-esp`（给 ESP32-C3/C6 用，约 200MB）列为必需依赖，每次构建都会尝试下载并卡住。

已修改 `~/.platformio/platforms/espressif32/platform.json`，把 `toolchain-riscv32-esp` 和 `tool-riscv32-esp-elf-gdb` 标记为 `optional: true`。

原文件备份在 `platform.json.bak`，需要恢复时直接拷回。
