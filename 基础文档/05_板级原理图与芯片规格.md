## 2. 原理图解读（网络级）

### 2.1 核心器件清单

| 位号 | 器件 | 说明 |
|---|---|---|
| U3 | **ESP32-S3-WROOM-1-N16R8** | 主模组，16MB Flash + 8MB 八线 PSRAM |
| U2 | **CH340C** | USB 转 TTL，接 UART0 |
| U1 / USB1 | TYPE-C 16PIN | **USB-OTG**，D+/D- → GPIO20/GPIO19 |
| USB2 | TYPE-C 16PIN | **USB-ISP**，D+/D- → CH340C |
| U11 | **WS2812B** | 板载 RGB，DIN ← GPIO48，VDD = 5V |
| U12 | 5V→3.3V LDO | 板载稳压 |
| D1/D2/D3 | B5819W SL | 肖特基二极管，USB 电源防倒灌 |
| Q1/Q2 | SS8050 | 自动下载电路（RTS/DTR 控制 BOOT/EN） |
| H1/H2 | X6511WV-22H | 2 × 22P 排针 |

### 2.2 关键网络连接

```
USB2(Type-C) ──CH340_D+/D-──► U2 CH340C ──U0TXD/U0RXD──► GPIO43 / GPIO44
                                    │
                                    ├─RTS─► Q1 ─► GPIO0 (BOOT)
                                    └─DTR─► Q2 ─► CHIP_PU (EN/RST)

USB1(Type-C) ──GPIO20 (D+) / GPIO19 (D-)──► ESP32-S3 原生 USB
              └─ R16/R17 5.1kΩ CC1/CC2 下拉

U11 WS2812B: VDD=5V, DIN=GPIO48, DOUT 悬空
```

### 2.3 由此确定的三条硬结论

1. **GPIO19/20 被原生 USB 占用**，GPIO43/44 被 CH340 占用 —— 这 4 个脚在任何情况下都不要接外设。
2. **板载 5V 与 3.3V 均可从排针取电**，但 D1/D2/D3 三只肖特基决定了：**同时插 USB 和外部 5V 会互相倒灌**，必须二选一。
3. **自动下载电路依赖 RTS/DTR**，因此 USB-ISP 口不能拿来做普通串口通信（会被 DTR 拉复位）→ 业务通信走 WiFi，不受影响。

## 3. 芯片级关键参数（摘自技术规格书 v2.2）

### 3.1 绝对最大额定值

| 项目 | 最小 | 最大 | 单位 |
|---|---|---|---|
| 电源电压 VDD3P3 / VDDA | -0.3 | 3.6 | V |
| IO 输入电压 | -0.3 | VDD+0.3 | V |
| 存储温度 | -40 | 150 | ℃ |
| ESD（HBM） | — | ±2000 | V |

### 3.2 推荐工作条件

| 项目 | 最小 | 典型 | 最大 | 单位 |
|---|---|---|---|---|
| VDD3P3_RTC / VDD3P3_CPU / VDDA | 3.0 | 3.3 | 3.6 | V |
| 工作温度 | -40 | — | 85 | ℃ |

### 3.3 功耗模式（用于电池续航估算）

| 模式 | 典型电流 | 说明 |
|---|---|---|
| Active（WiFi 发射） | **~240 mA 峰值 500 mA** | 正常工作时间歇出现 |
| Modem-sleep | ~20 mA | WiFi 连接但无收发 |
| Light-sleep | ~0.24 mA | 可被 UART/GPIO 唤醒 |
| Deep-sleep | ~7 µA | 仅 RTC 域 |

> 本车持续 WiFi 通信 + 电机控制，**不能进入 light/deep sleep**，按 240mA 均值估算。

### 3.4 GPIO 能力矩阵（选型依据）

| 能力 | 涉及 GPIO | 本项目用途 |
|---|---|---|
| ADC1（WiFi 下可用） | GPIO1~10 | 预留电池电压模拟采样 |
| ADC2（**WiFi 下不可用**） | GPIO11~14 | 不可用于模拟量 |
| 触摸 | GPIO1~14 | 未使用 |
| PWM（LEDC 任意脚） | 全部 | 电机、舵机、背光 |
| PCNT 输入 | 全部（矩阵） | 编码器 A/B |
| I2S | 矩阵任意 | 音频 |
| SPI0/1（内部） | 33~37 | **被 Flash/PSRAM 占用** |
| SPI2（FSPI） | 矩阵任意 | LCD + 触摸 |
| UART | 矩阵任意 | 雷达、日志 |
| USB | 19/20 固定 | 原生 USB |

## 5. 烧录方案

### 5.1 三种方式对比

| 方式 | 接口 | 速率 | 适用阶段 |
|---|---|---|---|
| Flash Download Tool | USB-ISP | 115200~921600 | 首次 / 救砖 |
| `idf.py flash` | USB-ISP 或 USB-OTG | 921600 | 开发期 |
| **OTA over WiFi** | WiFi | 取决于网络 | **主要方式** |

### 5.2 OTA 前置条件（首次必须做）

1. 首次用 USB 烧录一个**带 OTA 分区表 + WiFi 配网**的固件。
2. 分区表必须包含 `otadata` + 双 `ota_x` 分区（见 01 文档 §5）。
3. 固件内固化：设备 ID、WiFi SSID/密码（或 SmartConfig 配网）。
4. 后续升级：`esp_https_ota` 或自建 HTTP 服务器推送。

### 5.3 救砖流程

```
按住 BOOT(GPIO0) → 插入 USB-ISP → 松开 BOOT → Flash Download Tool 识别到 COM 口 → 烧录
```

若仍无法识别：检查 CH340 驱动（CH341SER）、换数据线（非充电线）、检查 3.3V 供电。

## 6. 软件抽象设计（板级硬件描述层）

> 本文档对应的代码层是"硬件事实的单一来源"，所有 GPIO 定义只能在这里出现一次。

### 6.1 常量与配置宏

```c
/* board_pinmap.h —— 唯一 GPIO 定义处，其他文件只能引用 */
#ifndef BOARD_PINMAP_H
#define BOARD_PINMAP_H

/* ===== 板载固定外设（不可改） ===== */
#define PIN_RGB_LED             48
#define PIN_BOOT_BTN            0
#define PIN_USB_DM              19
#define PIN_USB_DP              20
#define PIN_UART0_TX            43
#define PIN_UART0_RX            44

/* ===== 禁止使用（编译期断言） ===== */
#define PIN_RESERVED_USB_DM     19
#define PIN_RESERVED_USB_DP     20
#define PIN_RESERVED_PSRAM_0    35
#define PIN_RESERVED_PSRAM_1    36
#define PIN_RESERVED_PSRAM_2    37
#define PIN_RESERVED_UART0_TX   43
#define PIN_RESERVED_UART0_RX   44
#define PIN_RESERVED_FLASH_0    33
#define PIN_RESERVED_FLASH_1    34

/* ===== 板 1（主控）外设分配 —— 与汇总文档「引脚分配总表」一致 ===== */
/* ---- TB6612 电机驱动 ---- */
#define PIN_MTR_PWMA            4
#define PIN_MTR_AIN1            5
#define PIN_MTR_AIN2            6
#define PIN_MTR_PWMB            7
#define PIN_MTR_BIN1            15
#define PIN_MTR_BIN2            16
#define PIN_MTR_STBY            47      /* 受软件控制；拉低=高阻滑行，不可作急停（04 §4.1） */
#define PIN_MTR_VM_ADC          1       /* TB6612 ADC = VM/11，ADC1_CH0 */

/* ---- 编码器 ---- */
#define PIN_ENC_LA              17
#define PIN_ENC_LB              18
#define PIN_ENC_RA              8
#define PIN_ENC_RB              3

/* ---- I2C（MPU6050 + INA226 共用） ---- */
#define PIN_I2C_SDA             9
#define PIN_I2C_SCL             10

/* ---- 舵机云台 ---- */
#define PIN_SERVO_PAN           11
#define PIN_SERVO_TILT          12

/* ---- LCD + 触摸（共用 SPI2） ---- */
#define PIN_LCD_SCLK            13
#define PIN_LCD_MOSI            14
#define PIN_LCD_MISO            40      /* 触摸读坐标用 */
#define PIN_LCD_CS              38
#define PIN_LCD_DC              39
#define PIN_LCD_RST             42
#define PIN_LCD_BL              41
#define PIN_TP_CS               21
#define PIN_TP_IRQ              2

/* ---- 本板不接：摄像头 / 雷达 / 音频（分给板 2、板 3） ---- */

#endif /* BOARD_PINMAP_H */
```

> ✅ 上表已与汇总文档冻结版一致：**板 1 用满 25 个可用 GPIO，不占 strapping 脚（45/46）、不占板载 RGB（48）、不占 USB（19/20）与 UART0（43/44）**。
> 摄像头（14 脚 DVP）、雷达（UART）、音频（I2S+PDM）分配到板 2 / 板 3，避免 IO 冲突与 CPU 争抢。

### 6.5 接口声明

```c
/**
 * @brief  引脚占用登记（防止两个模块抢同一脚）
```

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 上电后不断重启 | GPIO35/36/37 被外接电路拉低 | 断开该脚 |
| 串口烧录失败 | 用了充电线 / CH340 驱动缺失 | 换线、装 CH341SER |
| WiFi 一发射就复位 | 5V 供电不足 | 换 ≥2A 电源，加 100µF 电容 |
| 烧录后程序不跑 | 启动模式脚（GPIO0/45/46）被拉错 | 检查外接电路 |
| PSRAM 分配失败 | `board_build.psram_type` 未设 opi | 配置为 `qio_opi` |
| ADC 读数乱跳 | 用了 ADC2（GPIO11~14）而 WiFi 开着 | 改用 ADC1（GPIO1~10） |
