### 1.3 关键结论（先看这五条）

1. **单块 ESP32-S3 装不下所有外设**。可用 GPIO 仅 25 个，而摄像头 DVP 一项就要 14 个。**必须三板分工**。
2. **雷达与摄像头必须与主控分离**。否则电机闭环（100Hz）会被 JPEG 编码打断。
3. **INA226 的 100mΩ 采样电阻只能测到 0.8A**，不能接在主回路。要么只测逻辑支路，要么改焊 10mΩ。
4. **系统有两套协议平面，不能混**：设备面（X-Protocol/UDP，只给固件和桥接）与客户面（JSON/WS，给浏览器和手机）。中间由 `web_gateway` 翻译兼做安全闸门。详见 `13`。
5. **开发必须"一次一块、故障不扩散"**。这不是风格偏好，是 16 份文档里唯一具有"宪法"地位的约束。详见 `14`；模块划分与缺口见 `15`。

### 2.3 为什么这样分

| 板 | 核心负载 | CPU 特征 | 分板理由 |
|---|---|---|---|
| 板 1 | 100Hz 闭环 + UI | 硬实时、低延迟 | 不能被任何耗时任务打断 |
| 板 2 | JPEG 编码 + 点云解析 | 高吞吐、可容忍 10ms 抖动 | 数据量大（400KB/s），独立 WiFi 流 |
| 板 3 | PDM 采集 + VAD + 播放 | 极轻（无推理） | 麦克风/喇叭物理位置限制，且 I2S 独占 |

**为什么三块板各自连 WiFi，而不是板间串起来由一块转发？**

| 维度 | 星型（采用） | 网关型（否决） |
|---|---|---|
| 摄像头带宽 | ✅ 独立走，不占控制板 | ❌ 400KB/s 过 UART 不够（3.2Mbps > 2Mbps 可靠上限） |
| 控制板负载 | ✅ 只跑电机+屏幕 | ❌ 要转发 400KB/s，污染 100Hz 闭环 |
| 单点故障 | ✅ 板 2 挂了车照跑 | ❌ 板 1 挂了全车失联 |
| 协议层数 | ✅ 一层 | ❌ 两层（板间 + 板↔主机） |
| 单独调试 | ✅ 任意一块可单独上电 | ❌ 必须三块齐了才能联调 |

> 代价是 WiFi 空口三路竞争。实测占用率约 15%（3.4Mbps / 20Mbps+），且视频做 pacing 后不构成瓶颈。

## 5. 通信协议契约

### 5.1 传输层

| 项 | 值 |
|---|---|
| 物理层 | WiFi 2.4GHz（802.11n） |
| 传输层 | **UDP**（控制/遥测），TCP 备用 |
| 端口分配 | 8888 控制遥测 / 8889 点云 / 8891 图像 / 8892 音频 |
| 寻址 | 笔记本运行固定 IP，三块板主动上报 |
| 心跳 | 板每 500ms 发 `0x13`；笔记本 2s 未收到判离线 |

### 5.2 帧格式（X-Protocol，全链路统一）

```
┌──────┬──────┬──────┬──────┬─────────────┬──────┐
│ 0xAA │ 0x55 │ LEN  │  ID  │  DATA (n B) │  CS  │
└──────┴──────┴──────┴──────┴─────────────┴──────┘

LEN = n + 5            （总帧长）
CS  = (0xAA+0x55+LEN+ID+ΣDATA) & 0xFF
多字节字段一律 **大端（Big-Endian）**
```

### 5.3 帧 ID 总表

| ID | 方向 | 名称 | 端口 | 周期 | 数据长度 | 状态 |
|---|---|---|---|---|---|---|
| **0x10** | 板1 → PC | 里程计 + **位姿** | 8888 | 50Hz | **17 B** | ⚠️ v1.0 扩展（原 6 B） |
| **0x11** | 板1 → PC | IMU | 8888 | 50Hz | 22 B | 新增 |
| **0x12** | 板1 → PC | 电源 | 8888 | 2Hz | 8 B | 新增 |
| **0x13** | 板1/2/3 → PC | 系统状态/心跳 | 8888 | 2Hz | **16 B** | ⚠️ v1.0 扩展（原 12 B） |
| **0x14** | 板3 → PC | 音频事件（VAD/播放） | 8888 | 事件 | 7 B | 新增 |
| **0x15** | 板1 → PC | 云台状态 | 8888 | 10Hz | 5 B | 新增 |
| **0x20** | 板2 → PC | 雷达点云分片 | 8889 | 70Hz | ≤253 B | 新增 |
| **0x21** | 板2 → PC | 图像 JPEG 分片 | 8891 | 10Hz | ≤1413 B | 新增 |
| **0x23** | 板3 → PC | 录音 PCM 分片 | 8892 | 事件 | ≤1200 B | 新增 |
| **0x50** | PC → 板1 | 速度控制 | 8888 | 20~50Hz | **7 B** | ⚠️ v1.0 加序号（原 6 B） |
| **0x51** | PC → 板1 | 云台角度 | 8888 | 事件 | 5 B | 新增 |
| **0x52** | PC → 板1 | 屏幕/灯效 | 8888 | 事件 | ≤32 B | 新增 |
| **0x53** | PC → 板3 | TTS 播放 | 8892 | 事件 | 变长 | 新增 |
| **0x54** | PC → 板2 | 图像参数 | 8891 | 事件 | 4 B | 新增 |

> **v1.0 两处协议变更的原因**
>
> 1. **`0x50` 加 `seq`**：UDP 虽在同一局域网内乱序罕见，但"旧指令覆盖新指令"是安全问题——若 `VX=+0.5` 的旧包晚于 `VX=0` 的新包到达，车会继续前进 20ms。加 1 字节序号即可低成本消除。
> 2. **`0x10` 加位姿**：v0.1 里板 1 自己积分位姿（`15` M13），但 `0x10` 只传速度，位姿没有传输通道，积分结果成了死数据；同时 `02` §9 又说上位机积分。**两处积分必然漂移不一致**。v1.0 定案：**板 1 是唯一积分源**，位姿随 `0x10` 上行，上位机只做转发与协方差填充。

### 5.4 核心帧详细定义

**`0x50` 速度控制（PC → 板1）— 7 B**
```
DATA[0]     seq      uint8            控制序号，0~255 循环
DATA[1..2]  VX       int16  ×1000 m/s     前进为正
DATA[3..4]  VY       int16  ×1000 m/s     两驱恒为 0
DATA[5..6]  VW       int16  ×1000 rad/s   逆时针为正
```

**乱序丢弃规则（板 1 侧实现）**

```c
/* seq 比较：允许回绕，只有"更新"的包才接受 */
static bool seq_is_newer(uint8_t in, uint8_t last) {
    int8_t d = (int8_t)(in - last);   /* 有符号差，天然处理 255→0 */
    return d > 0;                     /* 差 <=0 视为旧包/重复包，丢弃 */
}
```

- 首包（`last = 0xFF` 哨兵）无条件接受
- 同一 `seq` 重复到达 → 丢弃
- 差值 > 127 视为回绕后的旧包 → 丢弃
- **`0x50` 序号只用于"同一控制流内的新旧判定"**，不做重传、不做确认

**`0x10` 里程计 + 位姿（板1 → PC）— 17 B**
```
DATA[0]      seq      uint8            帧序号，0~255 循环
DATA[1..2]   RT_IX    int16  ×1000 m/s      左轮+右轮均速
DATA[3..4]   RT_IY    int16  ×1000 m/s      恒为 0
DATA[5..6]   RT_IW    int16  ×1000 rad/s
DATA[7..10]  pose_x   int32  ×1000 m        ★ 板 1 积分所得（世界系）
DATA[11..14] pose_y   int32  ×1000 m        ★
DATA[15..16] pose_th  int16  ×1000 rad      ★ 范围 ±32.7 rad，折算里程前需归一化
```

> **位姿精度说明**：`pose_x/y` 用 `int32 ×1000`，量程 ±2147483 m，精度 1mm，足够。
> `pose_th` 用 `int16 ×1000`，量程 ±32.7 rad（约 ±5.2 圈）。**板 1 侧必须把 `θ` 归一化到 `(-π, π]` 再打包**，否则跑几圈就溢出。

**位姿的唯一来源：板 1**

| 环节 | 责任方 | 说明 |
|---|---|---|
| 编码器计数 → 轮速 | 板 1 `mod_mtr` | 100Hz |
| 轮速 → 位姿积分 | 板 1 `mod_odom` | 100Hz，航迹推演 |
| 位姿 → `0x10` 上行 | 板 1 `mod_net` | 50Hz |
| `0x10` → `/odom` | 上位机 `robot_io` | **只转发，不重新积分** |
| 协方差 | 上位机 | 按经验值填，供 EKF 使用 |

> ⚠️ **上位机绝对不要自己再用轮速积分一次位姿**——两份积分初始条件和累积误差都不同，`/odom` 与 `tf` 会缓慢撕裂。`robot_localization` 的 EKF 只融合"板1 位姿 + IMU"，不再重复积分。

**`0x11` IMU（板1 → PC）**
```
DATA[0..1]   ax    int16 ×100   m/s²
DATA[2..3]   ay
DATA[4..5]   az
DATA[6..7]   gx    int16 ×100   rad/s
DATA[8..9]   gy
DATA[10..11] gz
DATA[12..13] roll  int16 ×100   °
DATA[14..15] pitch
DATA[16..17] yaw
DATA[18..19] temp  int16 ×100   ℃
DATA[20..21] 保留
```

**`0x13` 系统状态（三板上报）— 16 B**
```
DATA[0]     board_id    1=主控 2=感知 3=语音
DATA[1]     state       0=BOOT 1=IDLE 2=RUNNING 3=FAULT 4=OTA
DATA[2..3]  fault_code  uint16 位图
DATA[4]     wifi_rssi   int8 dBm
DATA[5..8]  free_heap   uint32 字节
DATA[9..12] uptime_s    uint32 ★ 由 uint16 扩展，18.2h → 136 年
DATA[13..15] version    3 字节 ★ 语义版本 major.minor.patch 各 1 字节
```

> **v1.0 两处修正**
> - `uptime_s` 原为 `uint16`，65535 秒 = **18.2 小时就回绕**，长时运行会误判"刚启动"。改 `uint32`。
> - `版本号低 8 位` 只能表示 0~255，无法区分 `0.1.1` 与 `0.2.0`。改为 3 字节 `major.minor.patch`，与固件 `FIRMWARE_VERSION` 宏一一对应。

**`0x20` 点云分片（板2 → PC）**
```
DATA[0]     seq     uint8   圈序号
DATA[1..2]  total   uint16  分片总数
DATA[3..4]  idx     uint16  当前分片
DATA[5]     count   uint8   本片点数
DATA[6..]   points  count × 4B
              每点: angle_cdeg(2B, 0~35999) + dist_mm(2B, 0=无效)
```

**`0x21` 图像分片（板2 → PC）**
```
DATA[0..1]  seq     uint16
DATA[2..3]  total   uint16
DATA[4..5]  idx     uint16
DATA[6..7]  len     uint16
DATA[8..]   jpeg    len 字节
```

### 5.5 超时与安全

| 场景 | 策略 |
|---|---|
| 板1 500ms 未收到 `0x50` | 自动减速到 0（斜坡 0.5s），上报 `0x13` 超时标志 |
| 板1 2s 未收到心跳 | 进入 IDLE，屏幕显示"离线" |
| 图像分片 500ms 未收齐 | 丢弃该帧（不补发） |
| 点云分片 200ms 未收齐 | 丢弃该圈 |
| 云端断连 | 板本地保持最后安全状态，不盲目运动 |

### 5.6 L2 客户面协议（概要，详见 `13`）

设备面用二进制，**客户面用 JSON**，两者由 `web_gateway` 翻译。

| 通道 | 类型 | 频率 | 内容 |
|---|---|---|---|
| `GET /api/status` | REST | 按需 | 全量状态快照 |
| `POST /api/estop` | REST | 事件 | 急停（不要求 token 新鲜度） |
| `WS /ws/telemetry` | JSON | 10Hz | odom / imu / batt / sys |
| `WS /ws/control` | JSON | 20Hz | `{vx, vw, seq}`（**必须有死手开关**） |
| `WS /ws/scan` | JSON | 5Hz | 180 点降采样 |
| `WS /ws/video` | **二进制** | 10fps | `seq(u32) + ts(u64) + JPEG` |

> 🔴 三条铁律：**不把 X-Protocol 暴露给浏览器**、**不把 ROS2 DDS 暴露到公网**、**不在没有死手开关的情况下做公网遥控**。

### 8.1 阶段划分

| 阶段 | 目标 | 交付物 | 验证标准 |

### 8.2 每个阶段的 SDD 循环

```

4. 实现      （AI 生成代码，人审核）

6. 归档      （更新设备文档中的"实测值"）
```

## 12. 框架选型结论（v2 · 已修订）

> ⚠️ **本节在 2026-11-07 修订**：语音识别从端侧移到上位机后，原先选 ESP-IDF 的唯一硬理由（esp-sr 仅 IDF 可用）消失，故改为 **PlatformIO + Arduino**。

### 12.1 主控固件：**PlatformIO + Arduino-ESP32 core 3.x**

| 理由 | 说明 |
|---|---|
| 硬约束已解除 | esp-sr 不再需要（识别在上位机） |
| 资料包自带 Arduino 例程 | TB6612、INA226、MPU6050、WS2812、屏幕、开发板全部有 |
| 底层能力不丢 | Arduino 是 IDF v5.x 的封装，`xTaskCreate`/PCNT/LEDC/`esp_timer`/`esp_ota_ops`/`lwip` 都能直接调 |
| AI 生成准确率高 | `setup()/loop()` + 库调用是训练数据里的主流模式；CMake/Kconfig 是 AI 易错区 |
| 迭代快 | 改一行 30 秒见效，三块板 × 十几轮调试差距会累积 |
| 三板共享代码 | 单工程 + 三个 `[env]` + 共享 `lib/`，比 IDF components 更直观 |

**必须遵守的四条纪律**

1. `platformio.ini` 里**钉死** `platform = espressif32@8.0.0`（对应 **Arduino-ESP32 core 3.3.12**），并在每份 spec 开头声明"使用 Arduino-ESP32 core 3.x API"（`ledcAttach()` / `ledcWrite(pin, duty)`）。

   > ⚠️ **v1.0 修正**：v0.1 写的 `espressif32@6.9.0` 是**错的**——该平台版本只带 Arduino core **2.0.x**，根本没有 `ledcAttach`，只有 `ledcSetup` + `ledcAttachPin`。AI 照 v0.1 生成 `platformio.ini` 会直接撞墙：代码按 3.x API 写，平台却是 2.x，编译报 `'ledcAttach' was not declared`。
   >
   > 版本对应关系（**这是硬绑定**）：

   | `espressif32` 平台 | 内置 Arduino core | LEDC API 形态 |
   |---|---|---|
   | 6.9.0 | 2.0.x | `ledcSetup()` + `ledcAttachPin()` |
   | **8.0.0（本项目）** | **3.3.12** | **`ledcAttach()` + `ledcWrite(pin, duty)`** |

   > 实际编译验证使用的是 `espressif32@8.0.0` + core 3.3.12（见 `16` §4.4）。
2. `board_build.arduino.memory_type = qio_opi`（N16R8 八线 PSRAM，配错会启动失败）。
3. 三块板同一 `lib/`，用 `-DBOARD_ROLE_MAIN/PERCEPTION/AUDIO` 切角色，**禁止复制三份代码**。
4. **分区表必须与 Flash 容量对齐**。N16R8 是 16MB Flash，`platformio.ini` 里需显式指定 `board_upload.flash_size = 16MB` 与自定义 `board_build.partitions`，否则默认分区表只给 app 3.2MB，OTA 双分区放不下。分区 CSV 属**冻结区**，改动需评审（见 `01` §5）。

**什么情况下改回 IDF**

- 400KB/s 图传在 `WiFiUDP` 上丢包严重（退路：`lwip/sockets.h` 裸 socket）
- 后期想在端侧做常听唤醒词（要 esp-sr）
- 需要 coredump 分析崩溃

### 12.2 上位机：**WSL2 (Ubuntu 22.04) + ROS2 Humble**

| 层 | 选型 |
|---|---|
| OS | Ubuntu 22.04 LTS（WSL2，`networkingMode=mirrored`） |

## 13. 附录 A：Arduino 栈 API 对照表

各设备文档里的**接口声明（模块契约）是框架无关的**，只有实现片段涉及具体 API。下表用于把 IDF 写法翻成 Arduino-ESP32 core 3.x。

| 用途 | ESP-IDF 写法 | Arduino core 3.x 写法 |
|---|---|---|
| GPIO 输出 | `gpio_set_level(pin, 1)` | `digitalWrite(pin, HIGH)` |
| GPIO 配置 | `gpio_config(&cfg)` | `pinMode(pin, OUTPUT)` |
| PWM 初始化 | `ledc_timer_config()` + `ledc_channel_config()` | **`ledcAttach(pin, freq, res)`** 一步到位 |
| PWM 占空比 | `ledc_set_duty()` + `ledc_update_duty()` | **`ledcWrite(pin, duty)`** |
| 编码器 | `pcnt_unit_config()` + `pcnt_unit_get_count()` | **`ESP32Encoder`**（内部就是 PCNT） |
| I2C 写 | `i2c_master_transmit(dev_h, buf, n, t)` | `Wire.beginTransmission(addr); Wire.write(); Wire.endTransmission()` |
| I2C 读 | `i2c_master_transmit_receive(...)` | `Wire.requestFrom(addr, n); Wire.read()` |
| I2C 初始化 | `i2c_new_master_bus(&cfg, &h)` | **`Wire.begin(SDA, SCL, 400000)`** |
| UART | `uart_driver_install()` + 事件队列 | **`HardwareSerial serial(1); serial.begin(230400, SERIAL_8N1, rx, tx)`** |
| 定时器 | `esp_timer_create()` | `esp_timer_create()`（**可用**，Arduino 也能调 IDF API） |
| 任务 | `xTaskCreatePinnedToCore()` | 同左（**完全可用**） |
| 日志 | `ESP_LOGI(TAG, ...)` | 同左（`esp_log.h` 可用） |
| 错误码 | `esp_err_t` / `ESP_RETURN_ON_ERROR` | 同左（`esp_check.h` 可用） |
| 屏幕 | `esp_lcd_*` | **TFT_eSPI** 或 **LovyanGFX** |
| 触摸 | `esp_lcd_touch_xpt2046` | **XPT2046_Touchscreen** |
| 摄像头 | `esp_camera_fb_get()` | **同左**（Arduino 库同名同签名） |
| OTA | `esp_https_ota()` | `ArduinoOTA` / `Update` 库，或直接调 `esp_https_ota()` |
| 非易失存储 | `nvs_get/set_*` | **`Preferences`** 库（底层就是 NVS） |

> **关键认知**：Arduino-ESP32 是 IDF 的封装，**IDF 的 API 在 Arduino 里基本都能直接调**。所以这不是"二选一"，而是"默认用 Arduino 便利 API，遇到库不够就下沉到 IDF"。

**给 AI 的提示词模板（建议固定加在每份 spec 开头）**

```
技术栈：PlatformIO + Arduino-ESP32 core 3.x（ESP32-S3, N16R8 八线 PSRAM）
约束：
1. 使用 core 3.x API（ledcAttach/ledcWrite，不是 ledcSetup/ledcAttachPin）
2. 引脚只从 board_pinmap.h 取，禁止硬编码数字
3. 多任务用 FreeRTOS（xTaskCreatePinnedToCore），不用第三方调度库
4. 禁止使用 GPIO35/36/37/19/20/43/44
5. I2C 用 Wire，SPI 用 TFT_eSPI，编码器用 ESP32Encoder
```
