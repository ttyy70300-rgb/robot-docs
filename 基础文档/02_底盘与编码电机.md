## 2. 关键参数

### 2.1 电机参数（MC130）

| 项目 | 数值 | 备注 |
|---|---|---|
| 电机类型 | 130 强磁直流减速电机 | 一体化包裹 |
| 额定电压 | **6 V（可用 3 ~ 9 V）** | 本项目 7.4V 供电，需降额使用 |
| 减速比 | **1:48**（默认）/ 1:90（可选） | 本项目按 1:48 |
| 编码器 | **13 线霍尔 AB 正交** | 磁环式 |
| 空载转速（1:48） | 约 200 rpm @6V | 7.4V 时约 240 rpm |
| 堵转扭矩（1:48） | 约 1.2 kg·cm @6V | 1:90 更大 |
| 输出轴 | 塑料（标配）/ 金属（带后壳款） | — |
| 接口 | **XH2.54-6P**（无后壳）/ PH2.0-6P（带后壳） | 两者不可混插 |

### 2.2 ⚠️ 编码器换算（最关键的数字）

| 减速比 | 电机轴线数 | 输出轴一圈脉冲 | **四倍频计数/圈** |
|---|---|---|---|
| **1:48** | 13 | 13 × 48 = 624 | **624 × 4 = 2496** |
| 1:90 | 13 | 13 × 90 = 1170 | 1170 × 4 = 4680 |

```
每米计数 = 2496 / (π × 0.065) = 2496 / 0.2042 ≈ 12223 counts/m
单计数位移 = π × 0.065 / 2496 ≈ 0.0818 mm
```

> 🔴 **陷阱**：塔克参考源码里写死 `WHEEL_RESOLUTION = 1560`（= 13×30×4，那是 MC520 电机）。用 MC130 1:48 时**必须改成 2496**，否则速度、里程计、PID 全部偏差 1.6 倍。

### 2.3 底盘几何参数

| 参数 | 符号 | 数值 | 来源 |
|---|---|---|---|
| 轮径 | `R` | **65 mm**（0.065 m） | 手册明确 |
| 轮距（左右轮中心距） | `W` | **待实测** | 参考值 0.162 m（R5 四驱 MC520） |
| 轴距 | `L` | 不适用（两驱） | — |
| 轮距修正系数 | `γ` | **待标定** | 参考值 1.75（四驱）；两驱建议从 1.0 起标 |
| 质量 | `m` | 0.3~0.6 kg（不含电池/主控） | 手册 |

> 🔴 **两驱差速不需要 γ**。γ 是四轮差速用来等效两轮时的修正系数。**两驱直接用真实轮距 W**：
> ```
> V_left  = Vx - Vw · W/2
> V_right = Vx + Vw · W/2
> Vx = (V_left + V_right) / 2
> Vw = (V_right - V_left) / W
> ```
> 参考源码的 γ=1.75 是四驱参数，**不要照抄到两驱**。

## 3. 接口定义

### 3.1 电机接口线序（XH2.54-6P，面向插头凸起朝上）

| Pin | 信号 | 说明 |
|---|---|---|
| 1 | **M+** | 电机正极 |
| 2 | **M-** | 电机负极 |
| 3 | **GND** | 编码器地 |
| 4 | **VCC** | 编码器电源（**3.3V 或 5V，视驱动板**） |
| 5 | **A** | 编码器 A 相 |
| 6 | **B** | 编码器 B 相 |

> ⚠️ **VCC 与 GND 接反会瞬间烧毁编码器**。塔克模块的电机口已标 3.3V，与 TB6612 模块的 `3V3` 输出对应。
> ⚠️ 不同厂家线序可能不同，接非塔克驱动板前必须万用表核对。

### 3.2 电机→TB6612 端口对应

| 底盘位置 | TB6612 端口 | 编码器 |
|---|---|---|
| 左后轮 | MOTOR A（AO1/AO2） | E1A / E1B |
| 右后轮 | MOTOR B（BO1/BO2） | E2A / E2B |
| 前万向轮 | — | — |

> **方向约定**：以车头向前为正方向。左轮正转 = A 相超前 B 相；右轮因镜像安装，**代码里需取反**（参考源码用 `R_Wheel_B.RT = -counter * scale`）。

## 4. 运动学模型（两驱差速）

### 4.1 坐标与符号约定（ROS 右手系）

| 量 | 含义 | 正方向 | 单位 |
|---|---|---|---|
| `Vx` | 前后线速度 | 前进为正 | m/s |
| `Vy` | 左右线速度 | **两驱恒为 0** | m/s |
| `Vw` | 绕 Z 轴角速度 | **逆时针（左转）为正** | rad/s |

### 4.2 逆运动学（上位机 `cmd_vel` → 左右轮速）

```
V_left  = Vx - Vw * W / 2
V_right = Vx + Vw * W / 2
```

### 4.3 正运动学（左右轮速 → 里程计）

```
Vx = (V_left + V_right) / 2
Vw = (V_right - V_left) / W
```

### 4.4 航迹推演（离散积分，周期 Δt）

```
x   += Vx * cos(θ) * Δt
y   += Vx * sin(θ) * Δt
θ   += Vw * Δt
```

> 差速模型 `Vy=0`，所以 `y` 方向只有 `Vx·sinθ` 分量。

### 4.5 轮速 → 编码器计数

```
counts_per_period = V_wheel * Δt / (π * R) * 2496
V_wheel = counts_per_period * (π * R) / 2496 / Δt
```

在 50Hz（Δt=0.02s）下，`V=0.3 m/s` 时每周期约 90 counts，分辨率足够。

## 5. 电机闭环控制（PID）

### 5.1 参考实现（塔克源码 `ax_speed.c`）

```c
// 增量式 PID
bias = spd_target - spd_current;
motor_pwm_out += kp * bias + kd * (bias - bias_last);
bias_last = bias;
// 限幅 ±4200（PWM 周期 8400，50% 占空比上限）
```

| 参数 | 参考值 | 说明 |
|---|---|---|
| `kp` | 800 | 参考源码默认 |
| `kd` | 1000 | 参考源码默认 |
| `ki` | 0（未使用） | 增量式隐含积分 |
| PWM 上限 | ±4200 | 对应 20kHz / 84MHz 时钟 |
| 控制周期 | 20 ms（50Hz） | 与里程计同频 |

### 5.2 本项目建议

| 项目 | 建议值 | 理由 |
|---|---|---|
| 控制周期 | **10 ms（100Hz）** | ESP32 算力充足，响应更快 |
| PWM 频率 | **20 kHz** | 超出人耳，避免啸叫 |
| PWM 分辨率 | 10 bit（0~1023）或 12 bit | LEDC 支持 |
| PID 结构 | 增量式 PI（kp + ki） | 纯 PD 有稳态误差，加小 ki |
| 初始参数 | kp=1.2, ki=0.05, kd=0.0（归一化后） | 需现场整定 |
| 抗积分饱和 | 输出限幅 + 积分分离 | 起步/堵转时防 windup |
| 死区补偿 | 前馈 8%~12% 占空比 | TT 马达低速死区明显 |

> ⚠️ TT 马达个体差异大、减速箱有回差，**不要追求高精度**。目标：直线 1m 偏差 <5cm，角速度阶跃响应 <300ms。

### 6.3 X-Protocol 帧格式（**必须严格遵守**）

```
┌──────┬──────┬──────┬──────┬─────────────┬──────┐
│ 0xAA │ 0x55 │ LEN  │  ID  │  DATA (n B) │  CS  │
└──────┴──────┴──────┴──────┴─────────────┴──────┘
 帧头1  帧头2  长度   帧码     数据区       校验和

LEN = n + 5                （总帧长，含帧头与校验）
CS  = (0xAA + 0x55 + LEN + ID + ΣDATA) & 0xFF
```

| 帧 ID | 方向 | 数据 | 说明 |
|---|---|---|---|
| **0x50** | 上位机 → 底盘 | **7 B**：`seq` uint8 + VX, VY, VW 各 int16 大端 ×1000 | 速度控制（含序号） |
| **0x10** | 底盘 → 上位机 | **17 B**：`seq` uint8 + RT_IX/IY/IW int16 ×1000 + `pose_x/pose_y` int32 ×1000 + `pose_th` int16 ×1000 | 里程计 + 位姿 |

**发送示例**（seq=0x07, VX=0.3 m/s, VY=0, VW=0.5 rad/s）：
```
seq  = 7             → 07
VX = 300 = 0x012C    → 01 2C
VY = 0               → 00 00
VW = 500 = 0x01F4    → 01 F4
DATA = 07 01 2C 00 00 01 F4
LEN  = 6 + 5 = 11 = 0x0B
CS   = (0xAA+0x55+0x0B+0x50+0x01+0x2C+0x00+0x00+0x01+0xF4) & 0xFF = 0x7C
完整帧: AA 55 0B 50 01 2C 00 00 01 F4 7C
```

### 7.8 任务

| 任务 | 核心 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|---|
| `task_mtr_ctrl` | 1 | 12 | 4096 | 10 ms | 读编码器 → 算速度 → PID → 写 PWM → 积分里程计 |

```c
void task_mtr_ctrl(void *arg)
{
    TickType_t last = xTaskGetTickCount();
    while (1) {
        for (int i = 0; i < 2; i++) {
            /* 读增量并清零（ESP32Encoder 内部用 PCNT，硬件四倍频） */
            int64_t cnt = s_enc[i].getCount();
            s_enc[i].clearCount();

            const float dt = MTR_CTRL_PERIOD_MS / 1000.0f;
            float mps = cnt * MTR_METERS_PER_COUNT / dt;
            if ((i == 0 && MTR_LEFT_INVERT) || (i == 1 && MTR_RIGHT_INVERT)) mps = -mps;

            s_wheel[i].rt_mps = mps;
            s_wheel[i].pwm    = mtr_pid_step(i, s_wheel[i].tg_mps, mps);
            mtr_pwm_apply(i, s_wheel[i].pwm);
        }
        kin_update_odom(MTR_CTRL_PERIOD_MS);
        vTaskDelayUntil(&last, pdMS_TO_TICKS(MTR_CTRL_PERIOD_MS));
    }
}
```

## 8. 错误处理与自检

| 检查 | 方法 | 处理 |
|---|---|---|
| 编码器无反馈 | 目标 >0.05 m/s 但 500ms 内计数为 0 | 置 fault=1，上报故障码 |
| 堵转 | PWM 饱和 >1.5s 且速度 <0.02 m/s | 置 fault=2，立即停机 |
| 轮速突变 | 单周期速度变化 > 2 m/s | 丢弃该周期数据（EMC 干扰） |
| 电池欠压 | 电压 < 6.4V | 禁止加速，仅允许减速 |
| 通信超时 | 500ms 未收到 `0x50` | 自动减速停车 |

## 9. 与上位机的契约

| 项 | 值 |
|---|---|
| 下行 | `0x50`（7 B）：`seq` uint8 + `VX, VY(=0), VW` int16 大端 ×1000 m/s、rad/s |
| 上行 | `0x10`（17 B）：`seq` uint8 + `RT_IX, RT_IY(=0), RT_IW` int16 ×1000 **+ `pose_x, pose_y` int32 ×1000 m + `pose_th` int16 ×1000 rad** |
| 频率 | 下行 20~50Hz；上行 **50Hz**（与 `/odom` 发布频率一致） |
| 超时 | 500ms 无下行 → 停车 |
| 坐标系 | ROS REP-103：x 前、y 左、z 上；θ 逆时针正 |

### 9.1 ⚠️ 位姿归属：板 1 是唯一积分源（v1.0 定案）

**v0.1 的矛盾**：`00` 里 `0x10` 只传速度，但 `15` M13 又说板 1 自己积分位姿——位姿没有传输通道，积分结果是死数据；同时本文档说上位机"由 0x10 + 航迹推演"发布 `/odom`。**两处各自积分，必然漂移不一致。**

**v1.0 定案：**

```
编码器 ──► 板1 mod_mtr（100Hz 轮速）
             │
             └──► 板1 mod_odom（100Hz 积分 → x, y, θ）
                    │
                    └──► 0x10（50Hz，速度 + 位姿）
                           │
                           └──► 上位机 robot_io：只转发，不重新积分
                                  │
                                  └──► /odom + tf(odom→base_link)
```

| 环节 | 责任方 | 说明 |
|---|---|---|
| 轮速计算 | 板 1 | 编码器 PCNT → m/s |
| **位姿积分** | **板 1（唯一）** | 航迹推演，100Hz |
| 位姿传输 | 板 1 → 上位机 | 随 `0x10` 上行 |
| `/odom` 发布 | 上位机 | **只做类型转换 + 填协方差** |
| tf 广播 | 上位机 | 用 `0x10` 里的位姿，不重新积分 |

**上位机侧对应**

| ROS2 话题 | 类型 | 方向 |
|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | 订阅 → 转 `0x50`（需加 seq） |
| `/odom` | `nav_msgs/Odometry` | **直接映射** `0x10` 的位姿与速度 |
| `/tf`（odom→base_link） | `tf2` | 用同一份位姿，**不重新积分** |

> **为什么不在上位机积分**：两份积分的初始位姿、时间步长、丢帧处理都不同，跑几分钟就会看到 `/odom` 和 `tf` 撕裂，表现为 RViz 里车体与轨迹分离。EKF（`robot_localization`）融合的是"板1 位姿 + IMU"，不再重复做轮式积分。

> **`θ` 归一化**：板 1 打包前必须把 `θ` 归一化到 `(-π, π]`，否则 `int16 ×1000` 只能表示 ±32.7 rad（约 ±5.2 圈）就溢出。
