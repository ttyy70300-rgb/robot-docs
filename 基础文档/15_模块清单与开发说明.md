## 3. 算法层（M01–M06）

> 全部无硬件依赖，`pio test -e native` 直接在 PC 上跑。**这一层必须先做完。**

### M01 · `proto` —— 协议编解码

| 项 | 内容 |
|---|---|
| 层 / 归属 | 算法 / 三板共用 |
| 依赖 | 无（只依赖 `<stdint.h>`） |
| 估行数 | 250 |
| 输入 | 各帧的结构体 或 原始字节流 |
| 输出 | 字节流 或 结构体 或 错误码 |

**具体做什么**

1. `proto_pack_*()`：把结构体打包成 `AA 55 LEN ID DATA CS` 帧（14 个帧 ID）
2. `proto_feed()`：逐字节喂入的流式状态机，输出完整的帧（帧头同步、长度校验、校验和验证）
3. `proto_calc_cs()`：累加和低 8 位
4. 坏帧处理：校验错/长度越界/帧头错位 → 丢弃并重新同步，**不卡死**

**接口**

```c
int  proto_pack_velocity(uint8_t *out, float vx, float vy, float vw);
int  proto_pack_servo(uint8_t *out, int16_t pan_cdeg, int16_t tilt_cdeg, uint8_t speed);
proto_err_t proto_feed(proto_ctx_t *ctx, uint8_t byte, proto_frame_t *out);
```

**缺资料** ⚠️

- `0x12` 电源帧的 `flags` 位定义（bit0 低压 / bit1 超量程 / bit2 离线，其余保留？）
- `0x13` 状态帧的 `board_id` 取值（1/2/3）与版本号字段（现在只有"低 8 位"，不够表达 semver）
- `0x52` 屏幕命令的 payload 结构（类型 + 参数，未定义）
- `0x53` TTS 播放帧的 `type/param` 语义

**验收**

- 14 个帧的 pack→unpack 往返一致
- 坏帧 20 种（截断、校验错、长度错、粘包、半包）全部优雅丢弃
- 单测覆盖率 >90%

### M02 · `kin` —— 运动学与里程计

| 项 | 内容 |
|---|---|
| 层 / 归属 | 算法 / 板1 |
| 依赖 | 无 |
| 估行数 | 200 |

**具体做什么**

1. `kin_inverse(vx, vw, W)` → `(v_left, v_right)`：逆解
2. `kin_forward(vl, vr, W)` → `(vx, vw)`：正解
3. `kin_odom_step(pose, vx, vw, dt)` → 新 `pose`：航迹推演（差速模型 `Vy=0`）
4. 角度归一化到 `-π~π`
5. 计数↔速度换算：`counts × (πD / 2496) / dt`

**缺资料** 🔴

- **轮距 W 实测值**（现在占位 0.162，是四驱 MC520 的参考值）
- **轮径实测值**（标称 65mm，压地后会变）
- 左右轮是否需要方向取反（接完线才能确定）

> 这三个不解决，`kin` 的系数全是错的，写出来也只能用占位值跑单测。**但可以先写、先测**（用参数化输入），实车标定后再填真值。

**验收**

- 给定轮速序列，位姿积分与手算逐点一致（误差 <1e-6）
- 直行时 `vw` 恒为 0
- 原地转一圈，`θ` 回到 0（±1e-3）

### M03 · `pid` —— 增量式 PID

| 项 | 内容 |
|---|---|
| 层 / 归属 | 算法 / 板1 |
| 依赖 | 无 |
| 估行数 | 150 |

**具体做什么**

1. 增量式：`out += kp*e + ki*e_dt + kd*(e - e_last)`
2. 输出限幅 + 积分分离（|e| 大时暂停积分，防 windup）
3. 死区前馈（TT 马�有 8~12% 死区）
4. 每轮独立实例（状态不可共享）

**缺资料** ✅ 无（参数需实车整定，但不阻塞编码）

**验收**

- 阶跃响应无超调（或超调 <10%）
- 长时间堵转后不 windup
- 限幅正确

### M04 · `lidar_parse` —— D6 点云解析

| 项 | 内容 |
|---|---|
| 层 / 归属 | 算法 / 板2 |
| 依赖 | 无 |
| 估行数 | 350 |

**具体做什么**

1. 两层状态机：外层解析 `A5 5A LEN CS TYPE`，内层解析点云包 `PH M&T LSN FSA LSA CS S1..Sn`
2. 距离解算：`Si_H*64 + (Si_2nd>>2)` mm
3. 强度解算：`(Si_2nd & 0x03)*64 + (Si_L>>2)`
4. 角度解算：起始/结束角 + 线性插值
5. 双字节异或校验
6. 起始包识别（`M&T bit0 == 1`）→ 一圈边界
7. 输出固定 400 点的极坐标数组

**缺资料** ⚠️

- **真实抓包样本**（工作状态下的原始字节流，`.bin`）
  现在只有协议文档和一个手写示例帧，无法做回归测试。
  → 获取方法：雷达 USB 接电脑，串口助手以 230400 保存二进制，转成 hex dump

**验收**

- 用真实抓包回放，解析结果与官方 Windows 上位机点云一致
- 坏帧、半包、校验错能恢复
- 单圈 400 点不缺

### M05 · `chunk` —— 通用分片与重组

| 项 | 内容 |
|---|---|
| 层 / 归属 | 算法 / 板2、板3 |
| 依赖 | 无 |
| 估行数 | 200 |

**具体做什么**

1. 发送侧：把一大块数据切成 N 片，每片带 `seq / total / idx / len`
2. 接收侧：按 `seq` 聚合，乱序补齐，收齐后回调
3. 超时丢弃（图 500ms / 音频 200ms）
4. 重复片去重、缺片检测

> **图像和音频共用同一套算法**，只是帧 ID 和超时不同。不做两份。

**缺资料** ✅ 无

**验收**

- 乱序到达能正确重组
- 丢一片时超时丢弃，不阻塞下一帧
- 重复片不重复写入
- 序列号回绕（uint16）不串包

### M06 · `vad` —— 语音活动检测

| 项 | 内容 |
|---|---|
| 层 / 归属 | 算法 / 板3 |
| 依赖 | 无 |
| 估行数 | 150 |

**具体做什么**

1. 每 10ms 一帧（160 样本 @16kHz），算 dBFS
2. 自适应噪声底（安静时慢速跟踪）
3. 双门限滞回（起始门限高、结束门限低）
4. 静音挂起计时（600ms 判定说完）
5. 最短语音时长过滤（<200ms 不算）

**缺资料** ⚠️

- **真实录音样本**：安静 / 正常说话 / 远处说话 / 电机运转噪声 / 风扇噪声
  用途：定 `AUD_VAD_THRESHOLD_DBFS`（现在 -42 是猜的），验证误触发率

**验收**

- 样本回放：误触发 <5%，漏检 <5%
- 电机启动瞬间不误触发
- 单句切分准确（起止误差 <100ms）

### M07 · `bsp_common` —— 板级基础服务

| 项 | 内容 |
|---|---|
| 层 / 归属 | 基础 / 三板共用 |
| 依赖 | Arduino-ESP32 core |

**具体做什么**

### M08 · `bsp_net` —— 网络

| 项 | 内容 |
|---|---|
| 层 / 归属 | 基础 / 三板共用 |
| 依赖 | `bsp_common` |
| 估行数 | 500 |

**具体做什么**

1. WiFi STA 连接 + 断线自动重连（指数退避）
2. 关闭省电模式（`WiFi.setSleep(false)`，否则延迟抖动）
3. UDP socket 收发封装（发送/接收/广播）
4. 心跳上报（2Hz `0x13`）
5. **IP 发现**：板子上电后主动告知上位机"我在线，我是 board N"
6. 时间戳（`millis()` → 上位机换算）
7. 连接质量统计（RSSI、丢包率）

**缺资料** 🔴

这部分是整个项目**最大的规划空白**，需要一次定清：

| 待定项 | 选项 | 影响 |
|---|---|---|
| 连谁 | 路由器 / 笔记本热点 / 专用 AP | 决定稳定性和 IP 段 |
| SSID/密码怎么配 | 硬编码 / AP 配网页 / 串口配置 | 改 WiFi 要不要重烧 |
| 信道 | 1/6/11 自动 or 固定 | 2.4G 干扰（现场扫） |
| IP 分配 | DHCP / 静态 | 板子 IP 变了上位机怎么找 |
| **IP 发现机制** | 广播 / 上位机扫描 / 板子主动上报 | 上位机要不要配三张 IP 表 |
| board_id 来源 | 编译宏 / MAC 派生 / NVS | 三块板烧同一份固件还是三份 |

> 建议方案（待你确认）：**路由器 + DHCP 保留 + 板子主动上报 board_id**，固件用编译宏区分三块板（`-DBOARD_ROLE_MAIN`）。这样上位机不需要配 IP 表，谁在线一目了然。

**验收**

- 断网 30s 内自动重连
- 三块板同时在线，心跳不丢
- 板子重启后上位机 3s 内重新识别

### M10 · `drv_tb6612` —— 电机 H 桥

| 项 | 内容 |
|---|---|
| 层 / 归属 | 驱动 / 板1 |
| 依赖 | Arduino GPIO/LEDC |

**具体做什么**

**缺资料** 🔴

- VM 分压比实测（原理图写 1/11，需万用表验）

**验收**

- 四象限动作正确（正转/反转/刹车/滑行）
- PWM 0 时电机短路刹车（不是惯性滑行）
- VM 读数与万用表误差 <0.1V

## 6. 功能层（M12–M22）

### M12 · `mod_mtr` —— 电机闭环

| 项 | 内容 |
|---|---|
| 层 / 归属 | 功能 / 板1 |
| 依赖 | `pid`、`kin`、`drv_tb6612` |
| 估行数 | 350 |

### M13 · `mod_odom` —— 位姿估计（唯一积分源）

| 项 | 内容 |
|---|---|
| 层 / 归属 | 功能 / 板1 |
| 依赖 | `kin` |
| 估行数 | 200 |

**具体做什么**

1. 消费 `mod_mtr` 的轮速快照 → 正解出 `vx/vw`
2. **航迹推演积分出 `x, y, θ`**，100Hz
3. `θ` 归一化到 `(-π, π]` 后再输出（`int16 ×1000` 量程只到 ±32.7 rad）
4. 提供 `reset(pose)`：上位机复位 / 重定位时调用
5. 输出 `pose_snapshot_t` 供 `mod_net` 打包进 `0x10`

> **v1.0 定案：板 1 是系统内唯一的位姿积分点。**
>
> v0.1 里 `0x10` 只传速度，位姿无处可去，这个模块的积分结果成了死数据；而 `02` §9 又写着"上位机由 0x10 + 航迹推演发布 /odom"，形成两处积分。现已在 `00` §5.4 扩展 `0x10` 为 17 B（含位姿），上位机只做转发。
>
> **因此本模块的验收必须包含"位姿确实上了总线"这一条**，不能只测内部变量。

**接口**

```c
typedef struct {
    uint8_t  seq;
    float    vx, vw;      /* m/s, rad/s */
    float    x, y, th;    /* m, m, rad（已归一化） */
    uint32_t stamp_ms;
} pose_snapshot_t;

void odom_reset(float x, float y, float th);
void odom_update(float vx, float vw, float dt);   /* 由 mod_mtr 100Hz 调用 */
void odom_get(pose_snapshot_t *out);              /* 由 mod_net 50Hz 调用 */
```

**缺资料** 🔴 同 M02（轮距/轮径）

**验收**

- 直行 1m，位姿误差 <5cm
- 原地转 360°，角度误差 <5°
- **`0x10` 帧中 `pose_x/pose_y/pose_th` 与模块内部值一致**（打包链路无截断/无符号错误）
- 连续运行 10 分钟（约 5 圈），`θ` 未溢出、未跳变

| 措施 | 成本 | 效果 |
|---|---|---|

- 14 个帧全通

- **乱序注入测试**：人为让 seq=5 在 seq=6 之后到达，车不得因此"倒退"到旧速度

### M21 · `mod_aud` —— 音频

| 项 | 内容 |
|---|---|
| 层 / 归属 | 功能 / 板3 |
| 依赖 | `vad`、`chunk`、`proto`、I2S |
| 估行数 | 350 |

**具体做什么**

1. PDM 采集 16kHz/16bit（DMA 环形缓冲）
2. 喂给 `vad` 判起止
3. 说话时推 PCM 分片（`0x23`）
4. 收 `0x53` 播放 PCM / 设音量 / 停止
5. 本地固定提示音（SPIFFS 里的 WAV）
6. 音频事件上报（`0x14`）

**⚠️ 硬约束：I2S0 单控制器全双工，采样率必须一致**

PDM RX（麦克风）与标准 I2S TX（NS4168 功放）**共用 I2S0**，两者共享同一个 MCLK 分频器。因此：

| 约束 | 值 | 违反后果 |
|---|---|---|
| RX 采样率 | **16 kHz** | — |
| TX 采样率 | **16 kHz（必须相同）** | 试图设成 44.1k → `ESP_ERR_INVALID_STATE`，或悄悄改掉 RX 时钟导致录音变调 |
| PDM 时钟 | 1.024 MHz（16k × 64） | — |
| TX BCLK | 512 kHz（16k × 32） | — |

**实现纪律**：`i2s_new_channel()` 一次拿到 TX+RX 两个句柄，**先定 16k 再初始化两个方向**；任何一方都不允许单独改采样率。若需播放 44.1k 音频，**在上位机重采样到 16k 再推**。

详见 `10` §4.2。

**缺资料** ⚠️

- **喇叭规格**（4Ω 3W？8Ω？）
- 麦克风与喇叭物理间距（防啸叫）
- VAD 门限实测值（见 M06）

**验收**

- 16kHz 采集连续无断点
- VAD 起止误差 <100ms
- 播放不卡、无爆音
- **同时录音与播放时，录音采样率仍稳定在 16kHz**（用频谱或已知音调验证不变调）

### M28 · `voice_tts` —— 语音合成

| 项 | 内容 |
|---|---|

**具体做什么**

**缺资料** ⚠️

- **引擎选型**：piper（本地、离线、音质一般）/ edge-tts（在线、音质好、需网络）

**验收**

- 合成延迟 <500ms
- 播放无爆音
- 能被打断

### M29 · `intent` —— 意图解析

| 项 | 内容 |

**验收**

- 20 条测试语句命中率 >85%
- 误触发不导致危险动作

### M30 · `web_gateway` —— Web 网关

| 项 | 内容 |
|---|---|

| 依赖 | FastAPI、rclpy |

**验收**

- 并发 3 客户端不崩
- 端到端延迟 <50ms（局域网）
- 无 token 拒绝访问、急停例外
